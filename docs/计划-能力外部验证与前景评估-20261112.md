### 0.3 RETECO 的真实竞争格局（联网核实）

RECOR 论文（RETECO Track 2 的上游）公开了 **23,768 个 turn 级观测**的完整对比：

| Retriever | Base | History+Reasoning |
|---|---|---|
| **DIVER**（reasoning 专用） | .347 | **.584**（95% CI .520–.649） |
| ReasonIR | .266 | .552 |
| **BM25**（词法） | .185 | **.489** |
| SFR（dense） | .240 | .464 |
| BGE | .230 | .445 |
| 平均 | .236 | .479 |

**两个关键事实：**

1. **BM25 在 History+Reasoning 下是 .489，超过所有 dense encoder（BGE .445 / SFR .464）。**
   这说明该赛道的胜负手是**查询表示（如何拼对话历史 + 推理）**，不是模型强度。
2. **顶配 DIVER 也只到 .584**，与 BM25 差 9.5 个点。天花板不高，但门槛也不低。

**对你的意义**：你零依赖、纯标准库，跑不过 DIVER/ReasonIR，但**有机会接近 BM25（.489）**——因为你的强项恰好是查询分析（`query.py` 的 `analyze_query`、说话人识别、别名索引）。

## 3. 阶段三：聚类 CI 方法论成文（1–2 周，优先做）

**这一步不依赖阶段一/二，可以并行或先做。**

### 3.1 为什么优先

你的 `data/diag_hist_pvalues.json` 里有一个**很少有人实测过的数**：

| 通路 | iid CI | cluster CI | 方差膨胀 |
|---|---|---|---|
| `bridge`+`reserve` holdout | [+0.51, +7.69] **不跨零** | [−0.83, +10.41] **跨零** | **2.94** |
| `quote_locate` holdout | [+1.03, +5.64] | [+0.85, +6.34] | 1.47 |
| `graph_reserve` holdout | [−0.51, +5.64] | [−0.83, +6.31] | 1.22 |

**结论：同一个系统、同一批答案，iid bootstrap 说显著，cluster bootstrap 说跨零。**

这正是 RAG 评测当前的痛点——大量论文用 iid bootstrap 报 CI，而题目是模板生成的（你实测 **1802 对 3-gram Jaccard ≥0.6 的近似重复**）。

### 3.2 核心论点（可直接写成 abstract）

> 现有 RAG 基准用 iid bootstrap 估计置信区间，但题目普遍由模板生成。
> 我们在一个 640 题的私有基准上实测：3-gram Jaccard ≥0.6 的近似重复达 1802 对，
> 按冻结模板簇做 cluster bootstrap 后，方差膨胀 **3.10–4.45**（估算值 1.9），
> CI 宽度膨胀 **2.11 倍**。这导致一条此前报告为显著的通路（iid CI [+0.51, +7.69]）
> 在正确口径下跨零（cluster CI [−0.83, +10.41]）。我们建议 RAG 评测默认报 cluster CI。

### 3.3 需要补的工作（不多）

| 项 | 现状 | 缺口 |
|---|---|---|
| 聚类方法 | `src/arkrag/cluster_ci.py` 已完成（319 行） | 无 |
| 实测数据 | dev/holdout/clean 三份齐全 | 无 |
| 多基准验证 | ❌ 只有 1 个私有基准 | **这是最大弱点** |
| 复现脚本 | `diag_hist_pvalues.py` 已有 | 无 |

**最大弱点：只有 1 个基准。** 审稿人会问"换个基准还成立吗"。

**补法（低成本）**：用 **RETECO 的 dev split**（519 queries，公开 qrels）或 **CRUD-RAG**（中文 RAG 基准，ACM TOIS 已发表）跑同一套 cluster CI 分析。不需要你的系统在那边表现好——**只需要有 per-query 的 pass/fail 向量**。

### 3.4 成本

- 多基准验证：3–5 天
- 写作：5–7 天
- **合计 1.5–2 周**

## 6. 明确的能力边界（诚实清单）

### 6.1 你确实强的

1. **引用可逐字验证**：`evidence_spans` 有真实偏移，`text[start:end]==evidence` 可机检。这不是"LLM 生成后拼引用"，是装配时算出来的。
2. **评测自我审计**：七轮对抗审查、12 种注水手法自曝、判据与金标全程未改。
3. **统计口径严谨**：主动发现 iid bootstrap 高估显著性，并量化了膨胀倍数。
4. **工程可复现**：零依赖、2276 测试、每项改动有"默认关闭 + 反向门"。

### 6.2 你确实弱的

1. **单一领域、单一语言**，且深度绑定中文游戏文本形态。
2. **绝对分数不可比**：自建 goldset（640 题）+ 自写判据。
3. **multihop 未解**：36% 属 `no_common_neighbor`，是你最大的失分项。
4. **没有外部基准验证**：这是学术界最看重的，也是你现在最缺的。

### 6.3 一句话总结

**你做出的不是一个"更好的 RAG 系统"，而是一套"更诚实的 RAG 评测方法"。**
前者的市场是榜单，后者的市场是会议。以你现在的架构，后者才是你的路。
