## 0. 先看清赛道的真实形状

### 0.1 官方评测口径（已核实）

| 项 | 2a | 2c |
|---|---|---|
| 官方排名指标 | turn 级 nDCG@10（`pytrec_eval` `ndcg_cut_10`） | turn 级 nDCG@10 **+** 五维生成评分（并列，不合成单一分数） |
| 聚合方式 | 每 turn 算 → 每域平均 → **11 域宏平均** | 同左 |
| 输入 | 对话历史 + 当前 turn + 该域全量语料 | 同左 |
| 输出 | 有序文档列表 | **top-5 passage + 生成答案** |
| 提交格式 | 六列 TREC：`query_id Q0 doc_id rank score run_id` | TREC run + UTF-8 JSONL（`turn_id`, `answer`） |

五维生成评分（1–5 Likert，`(score-1)/4` 归一后宏平均）：

| 维度 | 判什么 |
|---|---|
| Correctness | 事实对不对 |
| Completeness | 覆盖够不够 |
| Relevance | 是否答了当前需求 |
| Conversational coherence | 是否接得上对话 |
| **Faithfulness** | **是否有 passage 支撑** ← 你的主场 |

### 0.2 三个决定策略的数字

**数字一：隐藏测试集只有 ~200 个 turn。**

> Approximately 200 Track 2 target turns, stratified across all 11 RECOR domains.

⇒ **每个域约 18 个 turn**。因为 nDCG 是**按域宏平均**，所以 Drones（16,381 文档）与 Earth Science（121,249 文档）**权重完全相同**。

**这条直接改写优先级：先做小域，小域便宜且同样值钱。**

**数字二：BM25 的真实水位（dev，官方 starter kit）。**

| 输入表示 | nDCG@10 dev |
|---|---|
| 只给当前 turn | **0.1827** |
| turn + 对话历史 | **0.4379** |

⇒ 加入历史让同一检索器 **翻 2.4 倍**。**这就是这个赛道的主战场**——不是模型强度，是"如何把历史变成有效查询"。

**数字三：SOTA 与上界（RECOR 论文，23,768 turn 级观测）。**

| Retriever | Base | History+Reasoning |
|---|---|---|
| DIVER（reasoning 专用） | .347 | **.584**（95% CI .520–.649） |
| ReasonIR | .266 | .552 |
| **BM25** | .185 | **.489** |
| SFR（dense） | .240 | .464 |
| BGE | .230 | .445 |

⇒ **BM25 的 .489 高于所有 dense encoder（BGE .445 / SFR .464）。** 这是一个词法系统仍有竞争力的赛道。

**这是你的机会窗口**：零依赖、纯标准库的实现，只要把"历史表示"做对，就有机会逼近甚至超过官方 BM25 的 .4379。

## 1. 你的资产与缺口（诚实盘点）

### 1.1 能直接用的

| 资产 | 在 RETECO 上的价值 |
|---|---|
| `index.py` + `fts_backend.py`（FTS5） | 建英文索引，SQLite FTS5 本身支持英文分词 |
| `Retriever.search()` 的 BM25 主干 | 直接可用的 baseline |
| `query.py::analyze_query` | 查询分析框架可复用（但规则是中文的） |
| **`evidence_spans` 逐字偏移** | **2c 的 Faithfulness 维度直接受益** |
| **`cluster_ci.py`（聚类 bootstrap）** | **可用来评估 RETECO 自己的榜单稳定性** ← 见 §6 |
| `judge_v2.py` 三轴判据 | 可做本地 faithfulness 预检 |

### 1.2 会失效的（必须提前承认）

| 资产 | 为什么失效 |
|---|---|
| `quote_locate` | 依赖"题干里有 ≥8 字引文"，RECOR 英文问句没有这个形态 |
| `bridge` | 依赖两个「」锚点，英文语料零触发 |
| `vocab` / `alias_index` | 全部中文构建，`norm_entity` 的别名规则绑定中文称谓 |
| 图扩展通道（`expand`） | 没有预建图；RECOR 只给语料不给图 |
| 中文分词 | 英文需换 tokenizer（FTS5 的 `porter` 或 `unicode61`） |

**结论**：迁移后你的系统**退化为"BM25 + 查询分析 + 抽取式答案"**。
图通道、桥接、引文定位三条通路全部归零。

**这不是坏事**——它让实验变干净：你测的是"历史表示 + 抽取式 faithfulness"两个变量。

### 1.3 关键判断：2c 才是你的差异点

2a 是纯检索，你要和 BM25 .4379、DIVER .584 正面比，**大概率打不进前三**。

2c 有**五维并列评分**，其中 Faithfulness 是"answer 是否有 passage 支撑"。
**抽取式系统在这个维度上有结构性优势**：它只能从 passage 里摘句子，天然 faithful。

代价是 Completeness 与 Coherence 会低（抽取式答案不成段、不连贯）。

**这是一个真实且有价值的权衡实验**：抽取式 vs 生成式在五维上的分布差异。
SemEval 的 system paper 明确要求"explain where it succeeds or fails"，这正是。

### 阶段 3：主实验（第 4–6 周，12-03 → 12-23）

#### 3.1 历史表示（2a 的核心）

这是唯一被证实有效的杠杆（.183 → .438）。三个梯度：

| 变体 | 做法 | 预期 |
|---|---|---|
| H1 | 朴素拼接：`history + " " + current_turn` | 复现 .4379 |
| H2 | 角色标注：`Q: ... A: ...` 保留说话人结构 | 可能略优 |
| H3 | **查询分析式**：从历史中抽实体/术语，与当前 turn 加权融合 | **主实验** |

H3 的具体做法（复用 `query.py` 的思路但重写规则）：

1. 从 history 里抽 **content terms**（去停用词后的名词短语）
2. 当前 turn 里的代词/省略（`it` / `that` / `they` / 无主语）触发"历史补全"
3. 用 **BM25 分数加权融合**：`score = w1 * bm25(turn) + w2 * bm25(expanded)`
4. **在 train 上调 w1/w2，dev 只测一次**

> ⚠️ **纪律**：这是你自己项目踩过的坑——`answer.py:216` 为某道 holdout 题调参数，
> 导致 holdout 不再是确认集。**这次严格 train 调参、dev 只测一次。**

#### 3.2 2c 的抽取式生成

| # | 任务 |
|---|---|
| 3.3.1 | 用 top-5 passage 作为唯一证据源 |
| 3.3.2 | 抽取式答案：从 passage 里选最相关的 1–3 句 |
| 3.3.3 | **每条答案句带 `evidence_span`（字符偏移）** ← 复用现有机制 |
| 3.3.4 | 输出 JSONL：`{"turn_id": ..., "answer": "..."}` |
| 3.3.5 | 长度控制：官方 2c 无字数限制，但抽取式天然短；做一句/两句对照 |

**这是你的差异点**：答案句可以逐字回溯到 top-5 passage 的偏移。
虽然 LT 评分是 LLM 打的、不读你的偏移，但**它在 system paper 里是可验证的论据**。

#### 3.3 本地 faithfulness 预检

用 `judge_v2.py` 的 `support_ok` 轴跑本地自检：每条答案句是否能在 top-5 passage 里找到支撑。
**这不是官方指标，是你的内部一致性检查**。

## 6. 论文的真正增量：把 cluster CI 用到 RETECO 自己身上

### 6.1 为什么这是你的独特贡献

你已经实测过：**模板化题目的 iid bootstrap 会系统性低估 CI**。

> 在你自己的 640 题基准上：3-gram Jaccard ≥0.6 的近似重复 **1802 对**，
> 冻结模板簇 cluster bootstrap 的方差膨胀 **3.10–4.45**（估算是 1.9），
> CI 宽度膨胀 **2.11 倍**。一条 iid 口径显著的通路（[+0.51, +7.69]）
> 在 cluster 口径下跨零（[−0.83, +10.41]）。

**RETECO 的处境更糟**：
- 隐藏集 ~200 turn，按 11 域宏平均
- 每域 ~18 turn
- RECOR 的对话是**用 Decomposition-and-Verification 框架合成**的（论文自述），
  不同对话共享 5.87 个 aspect 模板

⇒ **这几乎是"iid bootstrap 必然高估显著性"的教科书场景。**

### 6.2 可以产出的三个数（都在你能力范围内）

| # | 分析 | 怎么做 |
|---|---|---|
| 6.1 | **dev 上的模板簇结构** | 对 858 个 dev turn 算 3-gram Jaccard，报簇数与有效样本量（Kish） |
| 6.2 | **自身两 run 差异的 cluster CI** | 用 `cluster_ci.paired_bootstrap_delta`，报 iid vs cluster 两套 |
| 6.3 | **"榜单可分辨性"上界** | 在 200 turn / 11 域下，两系统 nDCG 差多少才能显著？给出最小可检测效应（MDE） |

**6.3 是最有价值的一个**：它告诉整个赛道"在 200 turn 上，前 5 名之间可能无法区分"。

⚠️ **诚实边界**：这是对**别人榜单**的评论，必须极其克制。
- 不许说"榜单错了"
- 只说"在这个规模下，X 与 Y 的差异落在置信区间内"
- 必须给出完整的计算过程与假设

### 6.3 这一节如何改变"拿不拿名次"的价值判断

如果你拿到第 8 名，但能证明"前 8 名在统计上无法区分"，**这比第 8 名本身有价值得多**。

SemEval 的 system paper 明确说：

> A useful paper should make the system reproducible and explain where it succeeds or fails
> — not merely state its leaderboard position.

**你的论文标题可以是**：《在 200 个 turn 上，RAG 榜单能分辨什么？—— 一次带聚类置信区间的 RETECO 系统报告》
