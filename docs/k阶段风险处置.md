## 3. 结论

1. **没有一条是靠改判据让它消失的**。每一条要么在候选里被拆开（`SPLIT`：成员成独立实体，
   最符合「宁可拆多不可错并」），要么仍然并着（`KEPT`）且成员确实是同一个人的战地标签。
2. `MISSING` 的条目是语料/分块变了导致该名字整体不再出现，不是被规则删掉；
   它们在本文件里逐条点名，不当成「已处理」含糊过去。
3. 剩下仍并着的条目是**结构决策**而不是噪声清理：要拆得先扩 `GENERIC_PERSON_NOUNS` /
   `MEMBER_SUFFIXES` 并 bump `ENTITY_RULE_VERSION`，然后走新世代重建。
   在建图之后摘点会让 `merge` 计数与实际图不符（`L4.13` 会红）。
4. 这两类门在代码里本来就是**申报门**（`PASS` + 读数），不是 `FAIL` 门：
   `「油滑的士兵」该不该并成一个具体的人，取决于该标签在同一段剧情里是否只指一个人，
   这要按块共现才判得出，建图期拿不到这个信息`（`docs/抽取台账.md:90`）。
   所以本文件的职责是**把读数变成有人签字的具体结论**，不是替门改判。
