## 2. 运行纪律（血泪，必须遵守）

详见 `docs/事故-内存耗尽与熔断器-20261110.md`。核心三条：

### 2.1 任何加载产物的命令都必须走熔断器

```powershell
python scripts/run_guarded.py -- <命令>
```

`run_guarded.py` 的主机制是**内核级硬上限**
（`JOB_OBJECT_LIMIT_JOB_MEMORY`）：超限分配根本不会被满足，子进程当场
`MemoryError`，内存从没被真正占走。本机实测：Job 上限 64 MB、子进程要 200 MB
→ 退出码 42，`MEMORY_ERROR_CAUGHT`，整机 commit 稳在 10.6 GB。

**本轮我违规过一次**：直接跑了两条 `eval_answer_quality` 没过熔断器，
发现后 kill 并用熔断器重跑。教训记在台账 D-29，别再犯。

### 2.2 一次 `load_generation()` 常驻 1.0–1.5 GB

产物磁盘 302.4 MB（`lexical.json` 107 MB + `chunks.jsonl` 69 MB +
`assertions.jsonl` 69 MB + `graph.json` 32 MB + `adjacency.json` 26 MB）。
**并发五份就是 5–8 GB** —— 这是三次整机崩溃的共同成因。

### 2.3 不许用管道捕获输出

`pytest ... | Select-Object -Last 10` 会让读取等不到 EOF，表现为"工具返回空、
job 失踪"。**输出重定向到文件再读**是唯一可靠形态。

## 4. ★ 最需要人复核的一条：bridge 的 holdout 显著性消失了

这是本轮唯一推翻历史结论的发现，且它影响"生产档里 `bridge`+`reserve` 该不该留"。

用聚类 bootstrap 重算三条历史通路（`data/diag_hist_pvalues.json`）：

| 通路 | dev | holdout | clean |
|---|---|---|---|
| `quote_locate` | [+0.84,+4.92] | **[+0.85,+6.34]** | **[+0.71,+7.61]** |
| `bridge`+`reserve` | [+3.09,+11.62] | **[−0.83,+10.41] ⚠️跨零** | [−2.75,+11.01] ⚠️跨零 |
| `graph_reserve` | [+1.69,+6.96] | [−0.83,+6.31] ⚠️跨零 | [−3.06,+4.55] ⚠️跨零 |

- `quote_locate`：三份 cluster CI 全不跨零，**正向效应在聚类口径下依然显著**。
- `bridge`+`reserve`：holdout 的 iid CI 不跨零（+0.51），但 **cluster CI 跨零（−0.83）**，
  方差膨胀 **2.94**。**计划书记录的 iid CI[+5,+18] 的方向，在正确口径下证不出来。**
- `graph_reserve`：holdout/clean 跨零，**与历史 p=0.1562 一致，未被推翻**。

**边界必须说清**：`bridge` 那组是**组合臂**（bridge+reserve 同开 vs 同关），
Δ=+4.10pt（8 题），点估计为正、方向一致，只是 CI 跨零。
**这不等于"bridge 没用"**，而是"以 holdout 为确认集、以聚类为口径时证不出显著"。

**建议你做的判断**：这个结论是否足以改变生产档？我的立场是**不足以**
（点估计为正、dev 显著、clean 数据量小），但它**足以让"CI[+5,+18] 证明它有效"
这句话不能再说了**。

## 11. 我踩过的坑（避免重犯）

1. **`clean` 不是 `gold-v2.json` 的 `split` 值**，而是"holdout 里且不在 gold-v1 里"。
   按 `split=="clean"` 过滤得 0 题。口径见 `scripts/eval_answer_quality.py::pick_items`。
2. **`rank_bucket` 被一次编辑误删**，588 题全 `NameError`——但脚本对单题异常
   `except` 后记 `run_error` 而不中断，**退出码 0、表面"跑成功"、实际零有效数据**。
   **教训：`status` 分布必须每次核对，不能只看退出码。**
3. **`explain_v2` 的逐值见证在 `axes_detail.support.per_value`**，不是顶层 `values`。
   写错时 `values=0`、`by_level={}`——那种"空但没报错"的形态最骗人。
4. **提交说明文件两次被误入库**（`_cm.txt`、`_m.txt`）。`git add -A` 会吞掉根目录
   临时文件。要么先加 `.gitignore`，要么用 `git add <具体路径>`。
5. **PowerShell 里 `foreach` 多写一个分号**会 ParserError；中文内容 `print` 到
   cp936 控制台会 `UnicodeEncodeError`（`∉` 直接崩）。改文件走 Python
   `io.open(..., encoding='utf-8', newline='')`，别用 `Set-Content -Encoding`。
