## 1. 一句话结论

**v2 上线为并列口径，不替换 v1。** 核心证伪条件全部满足：
`FP = 0`、`PF` 逐题互斥归因、`v1` 产物逐位不变、地板三行必报、
聚类 CI 与 iid CI 并列（且实测方差膨胀 **4.45**，远超计划书估的 1.9）。

原始 v2 通过率 **204/285 = 71.58%**，比 v1 的 81.05% 低 **9.47pt**。
**这个下降不是缺陷，是设计目标**：它把 `multihop`「全列候选」从免费变成有成本。

## 2. 翻转四类（J1 核心）

| 类 | 计数 | 含义 |
|---|---|---|
| `PP` | **204** | v1 与 v2 都通过 |

### 2.1 `PF` 的互斥归因（27 题全部可解释）

| 桶 | n | 说明 |
|---|---|---|
| `cardinality_ok` | **26** | 实体精度超限 |
| `support_ok` | 1 | 值无支撑（且同时基数超 1） |

**27 道全部是 `multihop`**，逐题明细：

| `cardinality:over` | n |
|---|---|
| 1 | 2 |
| 2 | 4 |
| 3 | 9 |
| 4 | 9 |
| 5 | 2 |

`extra_values` 与 `cardinality_over` 数值相同，说明归因链自洽（多列了 N 个候选）。

**这 27 道正是计划书 §W4 开头点名的结构缺陷 #1**：

> 无精度项 ⇒ `multihop` 的最优策略是"全列候选"，唯一刹车是 `merge` 的 8 句。

v1 下这些题靠"答案里有一句同时含 gold 和锚点"就通过，哪怕同时列了 3–5 个错误候选。
v2 的 `cardinality_ok` 把它们抓住了——**这正是 W4 存在的理由**。

### 2.2 `FP = 0` 的意义

`FP=0` 意味着 **v2 没有放行任何 v1 拒绝的题**。这满足了计划书的硬要求：

> v2 不得把任何 v1=FAIL 改成 PASS，除非它能被归入预登记的 v1 误判修正。

本次**没有任何 v1 假阴性需要修正**，所以 `FP` 必须为 0，实测为 0。

## 4. 聚类 CI 实测（J4 的核心发现）

```
CI[prod]  iid 81.05% CI[76.49, 85.61]   cluster 81.05% CI[74.02, 87.96]
CI[v2]    iid 71.58% CI[66.67, 76.84]   cluster 71.58% CI[57.81, 81.99]

配对Δ(v1→v2)  n=285  簇 166
  iid     Δ=-9.47pt  CI[-12.98, -6.32]
  cluster Δ=-9.47pt  CI[-17.78, -3.71]

方差膨胀 4.4497（簇方差 0.00132209 / iid 0.000297121）
有效样本量 64.05（Kish）
簇结构：285 题 → 166 模板簇，最大簇 29，其次 24 / 23 / 20 / 18
```

### 4.1 这是本次最值得记的一个数

计划书 §W4 的估算：

> 按 `m̄≈2.5, ρ≈0.6` 估，**方差膨胀 ≈1.9，CI 宽度膨胀 ≈1.4**

**实测方差膨胀 4.4497，是估算的 2.3 倍。** CI 宽度：
- iid：`-12.98 − (-6.32)` = 6.66pt
- cluster：`-17.78 − (-3.71)` = 14.07pt
- **宽度膨胀 2.11 倍**（估算是 1.4）

计划书明确要求：

> 实测方差膨胀有配对样本才计算，否则标不可估计，**不用 `m̄≈2.5,ρ≈0.6` 的假设值冒充实测**。

本次给的是**实测值**。结论：**历史 p 值若按 iid 算，置信区间被系统性低估约 2 倍**。
计划书要求的那三条（`quote_locate` p=0.0021、`bridge` CI[+5,+18]、
`graph_reserve` hold p=0.1562）**尚未重算**——本项只交付了工具与 dev 实测。

## 5. 地板三行（J5）

| 地板 | 读数 | 分母 / 方法 | 校正指标 |
|---|---|---|---|
| 回显题干 | **68/285 = 23.86%** | 零检索，题干自带 gold 原样回显 | `(204−68)/(285−68) = 62.67%` |
| 形状 oracle | **285/285 = 100.00%** | 零检索，「锚点 + gold」拼一句 | **不可估计**（`floor=285 > pass=204`，正确拒绝） |
| gold 原文 | **171/285 = 60.00%** | 零检索，答案 = gold 原文 | `(204−171)/(285−171) = 28.95%` |

两点值得记：
1. **`gold 原文 60% < 生产 81%`** —— 说明生产链路确实在"加东西"，不是单纯复述 gold。
2. **形状 oracle 100%** 印证了计划书说的"形状 oracle 100% → 归零"这个 v2 设计目标——
   v1 下任何符合形状的答案都过，这是 v1 最大的漏洞。v2 的 `support_ok` 就是为它设计的。

## 9. 对台账的影响

**主指标不变，仍用 v1 的原始通过率。** v2 是**并列的第二口径**，
用于解释"分数意味着什么"，不用于替换历史读数。所有历史对比继续用 v1 口径。

理由：计划书明写"原始通过率继续为主指标；地板校正分数仅作探索性次指标"。
把 v2 的 71.58% 当主指标会让全部历史读数失去可比性，而 v2 的价值恰恰在于
**解释** v1 的分数为什么虚高（27 道 multihop 靠全列候选蒙过）。
