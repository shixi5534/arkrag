# 决策台账

> 计划书 §0.3 要求：每条记 **决策点 / 候选 / 选定 / 理由（为什么不是另一个）**。
> 门线数字一律从计划书附录 A 继承，本台账只记「形态等价」与「区间外自决」，不记下调。

## D-01 语料取哪一份产物

- 候选：A 仓库 `main` 分支工作树；B 最新 Release 资产 `zh_CN.zip` + `manifest.json`。
- 选定：**B**。字节校验 `sha256=46b10620…0aeb` 与清单一致后才解压。
- 为什么不是 A：`main` 工作树与最新 Release **不是同一份内容**（main 树 story 文件 1,917 / wordcount 8,425,976 字；Release 2,292 文件 / wordcount 9,339,866 字，且 Release 多出 `event_summaries.json`、`summaries.json`、`story_supplement.json`）。计划书在 L0 明确要求「不许在旧产物上判 PASS」，选 A 会让全部基线数字建立在过期输入上。
- 影响：计划书正文里我手写的 1,917/842.6 万字一组数字全部作废，以 `data/arkrag/l0_manifest.json` 为准。

## D-02 L0「首行标题缺失文档数 == 0」的等价判据

- 候选：A 判 NEEDS_HUMAN（形态不符就不测）；B 换成 `storyName` 字段缺失数==0。
- 选定：**B**。实测 0。
- 为什么不是 A：这门要防的失效是「解析器静默丢整篇」；本语料的标题在 `storyName` 字段而非首行，等价判据测的是同一个失效方向。门线数字仍是 0，未下调。

## D-03 doc_id 折叠小写

- 候选：A 用磁盘真实路径（`Obt/main/…`）；B 折叠小写（`obt/main/…`）。
- 选定：**B**。
- 为什么不是 A：磁盘目录是 `Obt/` 而三本索引（wordcount/storyinfo/summaries）一律写 `obt/`。取 A 会造出 823 条「有索引无文件」+ 826 条「有文件无索引」的假失配，把 L0 对账门变成噪声大会。折叠后 `storyinfo.json` 与文件集 **0 差 0**。真实路径仍保存在 `path` 侧，不与 doc_id 混用。

## D-04 prop 白名单来自全量实测而非抽样

- 候选：A 按 7 个抽样文件的观察写黑名单；B 全量遍历后写白名单。
- 选定：**B**。实测 121 个原样写法 / 79 个折叠名；折叠后 **只有 5 个携带正文**（`name` `multiline` `subtitle` `sticker` `animtext`），其余 74 个全部丢弃并归类，未登记 prop 进 `unknown_prop` 计数。
- 为什么不是 A：计划书 L1 明示「列表项兜底是最危险的默认分支」。抽样看到的 79 种里其实还藏着游戏数据的拼写错误变体（`delat/dealy/delau/daley/delya/dalay/delayt/delay9ti/stopmucis/musicvolune/palysound/charslsot/chaa/dialo/dialogs`），黑名单会漏。实测 L1.4 兜底占比 = **0**。

## D-05 `subtitle` 归旁白、`animtext` 归标题卡

- 候选：A `subtitle`→标题卡；B `subtitle`→旁白，`animtext`→标题卡。
- 选定：**B**。
- 为什么不是 A：实测 `subtitle` 正文是「夜幕降临。」「源石锅炉的轰鸣声并未减弱，高大的烟囱上方依然烟雾缭绕。」这类描述性散文（5,948 条 / 147,516 字），而归标题卡会让旁白通道凭空少掉 14.7 万字；真正的换幕标注是 `animtext`（248 条，形如「卡兹戴尔南部地区 / 1094年夏，巴别塔倒塌后」，带 `group_location_stamp` 说话人），它才是地点+年代戳。

## D-06 `sticker` 归引用（信件/文献）

- 实测 3,857 条 / 87,017 字，形如「亲爱的K先生：」「我在凌晨的曼斯菲尔德监狱里给您写信。」
- 选定：`quote` 轮次，进抽取。计划书术语表里「引用行」是四类互斥轮次之一，这是它在本语料的落点。

## D-07 场景硬边界 = 一个剧情文件

- 候选：A 文件；B 有 `Subtitle/Decision` 才切；C 黑场 `Blocker` 也切。
- 选定：**A**（签字四）。实测理由：黑场 `Blocker(a=1,block=true)` 全语料 72,564 个节点、平均每文件 31 次，用它切会把平均 4,000 字的文件切成 <120 字碎片，直接撞 L2.2 最小块长门；`subtitle` 在主线实测为 0。
- 现况：L2.4 跨场景块 **0**（构造性保证，并已由 chunk_id 前缀校验）。

## D-08 前导空格只做 lstrip，不编码成语义字段

- 实测 19.35%（81,878/423,072）正文节点带前导空白，`content:"   好痛……"`。
- 选定：`clean_text` 统一 `strip()`；不引入「内心独白」布尔字段。
- 为什么：把缩进当语义无证据支撑，且会改语料指纹，使 L0 冻结的数字全部作废。尾部空白 0.58%、内部连续空格 0.04%、字面转义序列 0 条、NBSP 1 条（来自 `story_variables.json` 的 `nbs` 变量）——NBSP 一并归一为普通空格，否则同一句话有两种字节形态。

## D-09 L1.3 判据收窄到「说话人标记形态」

- 候选：A 任何以 `**` 开头的行都算残留标记；B 只匹配 `**X**：` 形态。
- 选定：**B**。
- 为什么不是 A：A 会把醉汉台词「***！我宰了你！」判成解析泄漏（实测唯一一条命中就是它）。按 A 判 FAIL 会逼我删真实台词——这是「改数据去迁就指标」的反面。门线仍是 0，只是测的是它声称的那个失效；负例（被打码台词）留在库内并在门上申报计数。

## D-10 L1.2 拆成「文档元数据泄漏」与「世界内编码行」

- 实测：文档元数据/路径泄漏 0 条；世界内编码行 **17 条**（如「奥罗拉……前公民编号……LC0073458。」「LOG: ZOOT-SYS-INIT」「对接单位：VI03」）。
- 选定：前者进门（0，PASS）；后者**保留在语料里**，判 NEEDS_HUMAN，并计划由 L3 噪声过滤拒绝「编号形态」实体名（`LC0073458` 不该成实体，但「奥罗拉」该）。
- 为什么不是直接删行：`公民编号` 是 act42side 的剧情装置，删行等于销毁证据（不变量 3）。该修的是抽取判据，不是语料。

## D-11 L2.1 换成「原文覆盖率 + 渲染冗余率」双口径

- 计划书原文「块数 × 平均块长 与总字数之差 <10%」在本语料实测 **25.5%**（FAIL）。
- 归因：块正文带说话人前缀（实测 1,631,333 字）+ 1 轮次重叠 + 换行符；这是渲染形态的结构性增量，不是丢内容。
- 选定：窄口径 **L2.1a 原文轮次覆盖率 = 422,975/422,975 = 1.00**（漏 0 篇，这门真正防的是静默丢内容）；宽口径 **L2.1b 冗余率 = 1.219**，只申报不设门。
- 为什么不是把 10% 改成 30% 让它过：那等于用调门线掩盖口径错配，计划书 §5.3 反模式 21 正是这一类。

## D-12 分片键与装箱

- `obt/main` 章节实测 36 章（17 个正集 + `st/spst/tr` 系外传族），最大章 `main_ep14` 229 块、最小 1 篇。
- 选定：**LPT 装箱成 11 片、每片目标 200 块、同一章节不拆**；实测片间 201–229（极差 1.14 倍，过 L2.6 的 ≤2 倍）。
- 为什么不一章一片：实测最大章是最小巷的 **12.8 倍以上**，一片 401 块一片 14 块会让 2 片并行的全局并发预算长期吃不满，且失败隔离粒度失真。

## D-13 计划书的块数区间作废重报

- 计划阶段我给的 T1=1,300–1,700 块、全量=9,000–13,000 块是按「900 字/块 ÷ 原始字数」估的。
- 实测：**T1(obt/main) = 2,272 块**，全量 = **13,786 块**。差异全部来自 D-11 的渲染增量与场景边界。
- 处置：以实测为准重报成本区间（见 `docs/抽取台账.md`），不改分块参数去凑原区间。

- 实测：17 条（`LC0073458`、`ZOOT-SYS-INIT`、`对接单位：VI03` 等）。
- 选定（用户裁决）：**语料不动，抽取侧拒绝编号形态实体名**。落到 `gates.l3_trial_gates` 的 L3.T8 门，判据 `RE_CODE_NAME`。

## D-15 抽取执行者改为子代理本体（签字七）

- 变更：用户指令「抽取直接由你自己完成，不能用本地的网关和 7b 模型跑」。原签字六里「子代理只驱动、不当抽取模型」被推翻。
- 后果与补偿：不变量 7「同一份输入必须产出同一份输出」在模型层不再由 API 温度=0.1 保证。补偿措施三条——① `model` 固定写 `agent:qoder-subagent` 并进缓存键；② 缓存值仍是执行者**原始输出**，二次运行 100% 命中即视为可复现，不做重新生成；③ 提示词指纹 `e15fd6d13cb3ad61` 随回执落盘，改提示词必须 bump 版本。
- 可复现性的承担点从「模型确定性」转移到「产物不可变」。这条差异必须写进验收报告，不许假装等价。

## D-16 关系密度与 L5 门线的结构性冲突（T0 实测外推）

- T0 实测：20 块 → 原始提及 150、去重专名 110、关系 40；**每块 7.5 实体 / 2.0 边**；按 T0 口径 `2×边/实体 = 0.73`。
- 外推 T1(2,272 块)：抽取边平均度数约 **1.5–2.5**，孤立实体率约 **0.45–0.65**。
- 冲突对象：计划书 L5 门线「平均度数 > 6」「孤立实体率 ≤ 0.20」。
- 根因不是抽取质量：是「关系名闭合到 59 条」+「宁可漏抽不可错抽」+「台词块多以称名与叙述为主」三者叠加的必然产物。T0 里 21/59 关系名被实际使用，38 条从未使用——按计划书 L4 自己的判据（有从未使用的关系名说明词表设计有问题），**该裁的是词表，不是门线数字**。
- 处置：先出实测数字给人，不自行下调门线，也不用零信息量的结构边把度数抬过 6。

## D-18 T1 抽取范围从「仅主线」扩到「主线 + 活动 + 肉鸽 + 干员密录」

  - B 加上 `activities` + `obt/memory`（活动 + 干员密录）。

  | obt/memory | 3,138 | 是 |
  | obt/main | 2,272 | 是 |
  | obt/rogue | 373 | 是 |
  | obt/roguelike | 50 | 是 |

### 二、W1：cap 砍掉的是 gold 证据句
- cap=14 与 cap=16 都是 226（Δ−2），掉分全在 `direct_relation`：`q-dr-000006` / `q-dr-000022`。
- 机制：cap 按 `(-score, chunk_id)` 取前缀，`乌尔比安—海嗣` 那条 gold 断言所在单元排在第 15 名之后，被砍掉后答案凑不出"一句同时含两个锚点"，判据从 `one_claim_all_anchors_and_gold` 落到 `no_single_claim_with_all_anchors`。
- **W0 预测 cap=14 会丢 6.1% 已进上下文的 gold——实测丢失的那部分恰好包含本该答对的题。教训："gold 是否还在上下文"不等于"这题还能不能答对"。**
- 门控本身正确（`cross_chunk`/`multihop` 答案零变化，反证条件 3 未触发），cap 也确实生效（答案变化 128–136 题）。**不是接线事故，是方向不划算。**

### 三、W2：机制被证实，但兑现不成分数
- `find_bridge` 层面：57 道 dev multihop 中 `ambiguous` 8→0、`ok` 23→31，**8 道题真的被解出 top1**（梁洵/海嗣/伊西多/克莱芒/埃尼斯/特菲/星熊/芙蓉）。
- 端到端：**228→228，multihop 27→27，一动不动**。
- 根因：那 8 道题在基线里**本来就已经通过**（判据理由 `gold_linked_to_every_anchor`）。桥接只是把答案换个说法。
- **计划书推理链漏了一环**："候选唯一率 43.9% → top1 87.7% ⇒ 有大量本该能答被放弃"——但"候选不唯一"与"判据会失败"之间没有因果关系。claim 通路本来就能凑出那句共现。
- 真实缺口：dev multihop 26/57 = **45.6% 是 `no_common_neighbor`**（两个锚点在本次上下文里没有共同邻居），W2 完全管不到；另有 15/30 失败是 `no_claim_links_gold_to_any_anchor`。
- 校准可行（M0 通过）：`raw_margin` 单特征 7 桶，实测精度 0.80–1.00，全部 ≥ 2/3 阈值；`data/bridge_calib.json` 已落盘且往返读回 OK。但只有 31 个样本，最长桶 n=1。
- **给下一轮的建议**：multihop 下一步该查那 26 道 `no_common_neighbor` 在**全图**里有没有共同邻居——有则是上下文召回缺口（需要更多候选，与 W1 方向相反）；没有则这批题不可由桥接解决。
