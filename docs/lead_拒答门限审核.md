# 拒答正确率：这条门限连「永不拒答」都能过

用户目标里有一条「**拒答 ≥90%**」。本轮审的是这条门限本身有没有鉴别力。结论比 P3 那几条更糟：

**`abstain_accuracy` 完全不看答案对不对，只看「拒没拒」。所以一个「永不拒答」的退化系统在 dev 380 上得 0.9211、在 v1 220 上得 0.9364 —— 两者都已经过了 90%。而当前系统是 0.8553。也就是说，在这条指标上，现在的系统比「什么都不拒」还要差。**

---

## 0. 为什么写这一节

`abstain_accuracy` 是六个目标里唯一一个「越高越好、且看起来已经在 0.85 附近」的指标，很容易被当成「差 5 个点就到了」。实际上它不是余量 5 个点，它是**方向都画反了**：把它从 0.8553 提到 0.9211 的最省事办法，是**把所有拒答都关掉**。

## 1. 指标实现（`scripts/ask.py:296-299` 逐字）

```python
        # 拒答题正确率：期望行为确定（该拒 / 该答）的题才能算
        abstained = bool(ans.get("abstained"))
        if question:
            abstain_ok.append(abstained == should_abstain)
```

它比较的是 `abstained == should_abstain`。**答案文本一个字都没参与计算。** 于是两类方向相反的错误（该答却拒 / 该拒却答）被放进同一个分母互相抵消。

## 2. 三行拆解（dev 380 与 v1 口径各一份）

| 行 | dev 380 | v1 口径（220 题，v1-holdout 100 题不在本轮 base 里，已排除） |
|---|---|---|
| 应拒题数 | 30 | 14 |
| **应拒且拒 `a`** | **5**（0.1667） | **1**（0.0714） |
| 应拒却答 | 25（其中答案碰巧对 **0**） | 13（答案碰巧对 0） |
| 应答题数 | 350 | 206 |
| **应答却拒 `b`** | **30** | **16** |
| 其中答案其实对 `c` | **0** | **0** |
| **混算现值** | **0.855263** | **0.868182** |
| 真改善判据 `350−b == c` | **不成立**（320 ≠ 0） | **不成立**（190 ≠ 0） |

**应拒侧的拒答率只有 0.1667（dev）/ 0.0714（v1）** —— 30 道应拒题里 25 道被答了。这才是真实的拒答能力。

拒答原因两侧**全是同一个** `no_supported_claim`（应拒侧 5、应答侧 30），说明拒答不是由「该不该答」决定的，而是由「抽取器有没有拼出一条能站住的 claim」决定的 —— 与题目的可答性无关。

## 3. 退化策略得分：门限的鉴别力检验

| 策略 | dev 380 | v1 220 | 是否已过 90% |
|---|---|---|---|
| **永不拒答**（`abstained` 恒 False） | **0.921053** | **0.936364** | **是** |
| 永不回答（`abstained` 恒 True） | 0.078947 | 0.063636 | 否 |
| **当前系统** | 0.855263 | 0.868182 | 否 |

⇒ **「永不拒答」这条最差的策略，得分比现在的系统还高 6.6 个点（dev）/ 6.8 个点（v1）。**

原因是算术上的必然：应拒题只占 7.9%（dev）/ 6.4%（v1）。只要应拒题占比低于 10%，「永不拒答」就自动 ≥ 0.90 —— 这条门限在**本题集上恒定可过**，与系统好坏无关。

**所以现在这个 0.8553 的真实含义不是「差 6.5 个点」，而是「比最差策略还低 6.6 个点」。**

## 4. 达到 90% 的算术解空间

| 口径 | 90% 需要正确题数 | 当前正确 | 还差 | 免费额度（`b` 里本来对的 `c`） | 免费后还差 |
|---|---|---|---|---|---|
| dev 380 | 342 | 325 | **17** | **0** | 17 |
| v1 220 | 198 | 191 | **7** | **0** | 7 |

**免费额度是 0** —— 因为没有一道「被误拒的题」答案本来是对的。也就是说，不存在「只要不拒就自动变好」的题。

可降额只有两处：dev 是「应拒却答 25 + 应答题被拒 30」；v1 是「13 + 16」。这两处**恰好就是两类方向相反的错误**，正是被混算抵消掉的那部分。

按类拆（dev 380）：误拒全部集中在 `single_chunk 18 / cross_chunk 6 / alias 5 / adversarial 1`；`negative_abstain` 38 题里应拒 30、拒对 5、误拒 0。

## 5. 对门禁的影响（四条）

1. **`abstain_accuracy` 不能单独作门限**。它是「拒答率代理」，不是「拒答正确率」；而且它的分子里不含答案正确性，应拒占比低时退化策略必然通过。
2. **发布清单这一行必须拆成三行**：应拒题拒答率 `a/N拒`（当前 0.1667 / 0.0714，离 90% 差得远）、应答题误拒率（当前 30/350 = 8.6%）、以及 `b` 里答案其实对的 `c`（当前 0）。**只有 `N答 − b == c` 才算真改善**；`c = 0` 而 `b` 下降 = 纯风险敞口。
3. **「拒答 ≥90%」这条目标要重新定义**。按现在的写法，任何系统只要不拒答就达标，这条目标没有信息量。合理写法是「**应拒题正确拒答率 ≥90%**」（当前 5/30 = 16.7%，这才是真差距）**且**「应答题误拒率 ≤ X%」**且**「答案正确性不低于基线」三条并列。
4. **不许把 0.8553 → 0.9211 当成「提升 6.6 个点」**。那 6.6 个点是「把所有拒答关掉」的收益，代价是应拒题全错、且这 25 道题会「自信地答错并附满引用」（P3 cross_chunk 已经实测过这个形态）。

## 6. 限制

1. 只用 dev 380 / v1 220 两个**已被实现跑过**的口径；new-holdout 160 一题未跑。v1 口径里 100 道 v1-holdout 不在 `data/a_p3_chapter_round.json` 的 base 里，已排除并在表里写明（**不许把这个 220 叫成「v1 320」**）。
2. 状态是 `CHAPTER_ANSWER_PATH=False`、`TITLE_ANSWER_PATH=False`（仓库默认）。标题通路开着时误拒会下降，届时三行都要重算。
3. 「答案碰巧对」用的是 gold 答案字符串子串判据（与项目一致），`negative_abstain` 的 gold 多为「否」这类单字，子串判据偏宽松 —— 但实测两侧都是 0，不影响结论。
4. 退化策略是**算术推演**（`n_ans/total`），不是真跑了一个「永不拒答」的系统。它的意义是「界」，不是「实测得分」；写报告时要标明这一点。
5. 复算：`py -3 scripts/lead_abstain_audit.py --json data/lead_abstain_audit.json`，产物 4,832 B。
