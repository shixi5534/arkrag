# 方向题正确率：这条门限现在没有判据

用户六大目标里有一条「**方向题 ≥95%**」。本轮审的是：这个数现在是**怎么算出来的**、它能不能支撑 pass/fail。

结论先写：**不能。** 现报的 `direction_accuracy` 不是方向判据，它与 `answer_hits_gold` 逐题恒等；而它覆盖的另一半题（multihop）里根本不存在「方向」这个可测量对象。在把判据定义出来之前，这条门限只能记 `unknown`。

---

## 0. 为什么写这一节

P3 之后的每一份报告都在报 `direction_accuracy`，用户的目标是 95%。如果这个数其实是「金标答案字符串有没有出现在答案里」，那么它是**答案命中率的第二次计数**，涨它不等于方向判断对了。这件事必须先定清楚，否则 P4 发布门里这一行永远无法判 pass/fail。

## 1. 指标实现（`scripts/ask.py:305-311` 逐字）

```python
        # 方向题正确率：direct_relation 与 multihop 都依赖方向语义
        if category in ("direct_relation", "multihop") and not should_abstain:
            gold_answer = str(item.get("answer") or "")
            ok = (not abstained) and gold_answer and gold_answer in str(ans.get("answer") or "")
            direction_ok.append(bool(ok))
```

四件事都没做：**没取主体、没取客体、没绑谓词、没比顺序**。它只问一句「金标答案字符串在不在答案里」。

## 2. 恒等检验：它与 `answer_hits_gold` 逐题相同

dev 应答题（`split == "dev"` 且非 `should_abstain`），逐题比对：

| 题类 | n | 逐题一致 | 不一致 |
|---|---|---|---|
| `direct_relation` | 57 | **57** | 0 |
| `multihop` | 57 | **57** | 0 |

⇒ **`direction_accuracy` 在其定义域上就是 `answer_hits_gold` 的第二次计数，零新增信息。** 一个指标只要与另一个指标逐题恒等，它在门禁里就不该占一行——它不会比另一个更早变红，也不会更晚。

## 3. 严判据对照：`direct_relation` 的真值低 4 题

严判据（本脚本 `2_direct_relation_严判据`）：答案里必须切出一条三元组 `(S, P, O)`，其中 `P` 等于金标谓词；**对称关系**（`vocab.SYMMETRIC_RELATIONS` 那 9 个：交战/交谈/亲属/冲突/同盟/同行/敌对/研究/称为）只要求 `{S,O} == {金标主体, 金标客体}`，**非对称关系**要求 `S == 金标主体 且 O == 金标客体`。

| 判据 | 判真 | 比例 |
|---|---|---|
| 旧（子串） | 45 / 57 | 0.7895 |
| 严（三元组绑定） | **41 / 57** | **0.7193** |

降级 4 题，逐题原因（都能用答案原文核对）：

| 题号 | 金标断言 | 对称 | 降级原因 | 答案 |
|---|---|---|---|---|
| `q-dr-000012` | 乌萨斯远北地区 --位于--> 乌萨斯 | 否 | 主体错（客体对） | `布列斯克位于乌萨斯。乌萨斯持有石棺。` |
| `q-dr-000020` | 萨卡兹 --交战--> 维多利亚 | 是 | 主体客体都不对，只是「交战」这个词同名 | `…查尔斯·林奇交战萨卡兹…` |
| `q-dr-000044` | 均 --持有--> 书刀 | 否 | 主体错（客体对） | `司岁台持有书刀。…` |
| `q-dr-900023` | 乌萨斯 --敌对--> 整合运动 | 是 | 主体错（客体对） | `…迷迭香敌对整合运动…` |

断言不可用 0、切不出三元组 0 —— 这 4 题的降级不是解析失败，是**系统真的把主客体配错了**。旧判据只看「金标答案没出现」，而这 4 题的答案里出现了**同一个关系词配错端点**，恰好绕过了旧判据。

## 4. `multihop` 那 57 题：不存在「方向」

该类金标答案是**单一中间实体名**。例：问「已知「云兽」通过唯一一个中间实体与「变形者集群」相连…这个中间实体是谁？」→ 金标答 `阿米娅`。

答案文本是一个名字，**没有主体、没有客体、没有谓词** ⇒ 在 57 题上「方向正确率」无对象可测。实测：答案里出现「两端点 1 跳共同邻居名」的 **30/57**，没有的 **27/57**；拒答 0。

⇒ 把 `multihop` 放进「方向题」的分母，等于把一批**没有方向属性**的题算进方向指标。这批题该按「中间实体是否命中」单独计，不该借方向指标的名义。

## 5. 合计真值，以及一个必须写清的口径差

dev 应答题 114 题（57 + 57）：

| 口径 | 判真 | 比例 |
|---|---|---|
| 旧（现报） | 70 / 114 | 0.614035 |
| 真（严判据 + multihop 换成共同邻居名命中） | 71 / 114 | 0.622807 |

分项：`direct_relation` 旧 45/57 = 0.7895 → 真 41/57 = **0.7193**；`multihop` 旧 25/57 = 0.4386 → 真 30/57 = **0.5263**。

**注意口径差**：`data/eval_snapshot_*.json` 里报的 `direction_accuracy = 0.666667（n=96, skipped=224）` 是 **gold-v1 320 题**口径（96 = v1 的 48 + 48），与本节的 dev 114 题**不同源，不可互比**。同一份快照三处分母（`mixed 300 / reachable 194 / ungated 75`）也是 v1 口径。

## 6. 对门禁的影响（三条）

1. **「方向题 ≥95%」当前必须记 `unknown`**。判据没定义，任何数都不能判 pass 或 fail；写 fail 也不对——因为它测的不是这件事。
2. **`direction_accuracy` 不能与 `answer_hits_gold` 同时占门禁两行**。二者逐题恒等，两行会让人以为有两个独立证据。要么删一行，要么把方向判据真正实现后再加回来。
3. **`direct_relation` 的真值要按严判据报**（41/57 = 0.7193），并且**必须并列对称关系免顺序的处理**——否则 9 个对称关系上的「顺序对」会被算成「方向对」。

## 7. 我这一轮自己踩的坑（留档）

第一版脚本把 `multihop` 的判据写成 `mid in (a1 & a2) and not abstained`，而 `mid` 是**金标答案本身**（中间实体名）。这等于在检验「金标答案在图里成立 ∧ 我们没有拒答」，**完全没看我们的答案**，于是跑出 57/57 这种漂亮结果。

真判据必须用「**我们答案里出现的实体名** ∩ 两端点 1 跳邻居集」。改完后是 30/57。

这是本项目第 N 次同族错误：**把「金标自身成立」当成「系统答对」**。与 `invalid_cache_report()["total"]`、`source_fingerprint` 那两个是一类——**判据里出现了金标自己的字段，那个判据就一定恒真**。

## 8. 限制

1. 只用 dev 应答题，不外推到 new-holdout 160（验收集一题未跑）。
2. 三元组靠 48 个关系词切分；实体名里若含关系词会切错。本轮切不出三元组 0 题，但这是本批数据的结果，不是保证。
3. 「严判据」只对 `direct_relation` 有定义（金标断言唯一，能取到 `subject_id`/`object_id`）；`multihop` 的「真值」只是「答案里有没有共同邻居名」，比旧判据强，但仍不等于「两跳路径正确」。
4. 本节所有数来自 `data/a_p3_chapter_round.json` 的 base 侧（`CHAPTER_ANSWER_PATH = False`、`TITLE_ANSWER_PATH` 按仓库默认 False），与 `eval_snapshot_title_on` 的状态不同，**不许跨状态引用**。
5. 复算方式：`py -3 scripts/lead_direction_audit.py --json data/lead_direction_audit.json`，产物 `data/lead_direction_audit.json`（2,155 B）。
