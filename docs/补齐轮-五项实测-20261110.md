### 1.2 `bridge` + `graph_reserve`（两者同时开 vs 都关）

**这是本轮最重要的发现。**

- 计划书记录的 `bridge` CI 是 **[+5, +18]**（iid 口径）——本次 iid 重算得 [0.51, 7.69]（holdout），
  与历史值**不一致**，因为答案集变了（生产档新增了 `chapter_cap=4`，且 W2 未开）。
- 关键点不在数值变化，而在**口径**：holdout 的 iid CI 不跨零（+0.51），
  但 **cluster CI 跨零（−0.83）**。方差膨胀 **2.94**。
- **结论：`bridge` 在 holdout 上的效应，在正确的聚类口径下不显著。**
  dev 仍显著（cluster [+3.09, +11.62]），clean 本来就跨零。

| split | n | Δ | iid CI | cluster CI | 膨胀 |

### 1.4 三条通路的结论汇总

| 通路 | dev | holdout | clean | 判定 |
|---|---|---|---|---|
| `quote_locate` | 显著 | **显著** | **显著** | 三份都稳 |
| `bridge`+`reserve` | 显著 | **跨零（cluster）** | 跨零 | **holdout 不显著** |
| `graph_reserve` | 显著 | 跨零 | 跨零 | 仅 dev 显著 |

**必须写清的边界**：这不等于「`bridge` 没用」。它是一个**组合臂**

点估计为正、方向一致，只是**置信区间在聚类口径下跨零**。
计划书要求"在新 cluster CI 出来前不预写结论"——现在出来了，如实记下：
**holdout 上这条通路的显著性不成立，不能再说"CI[+5,+18] 证明它有效"。**

## 5. W1 K4：延迟（3 轮交替，同机同缓存）

| 轮 | base P95 | cap P95 | 变化 |
|---|---|---|---|
| 1 | 306.61 | 290.24 | **−5.3%** |

| 合并 | **343.51** | **279.98** | **−18.5%** |

P50：206.8 → 170.1（**−17.6%**）。

### 5.1 两个判定必须分开

| 判定 | 结果 | 说明 |
|---|---|---|
| **绝对**（vs 计划书 136.6ms × 1.05 = 143.43） | **FAIL** | 本机基线实测 343.51ms，是 136.6 的 **2.5 倍**。这个判定测的是**环境差异**，不是 cap 的影响 |
| **相对**（同机、同轮、同缓存交替） | **PASS** | 三轮全降，P95 −18.5%，无一轮上升超过 5% |

计划书的 136.6ms 是旧环境（全局 Python 3.14.3 + 无 `chapter_cap`）的读数。
本机（conda 3.13.18 + 生产档含 cap=4）基线已漂到 343.51ms。**用 143.43 当门槛，
两臂都会 FAIL，那个结论毫无信息量。** 因此同时报两个判定，并明确哪个可比。

**K4 的本意是"cap 不能让延迟上升"。三轮交替实测都下降，按本意 PASS。**

## 6. W4：`witness_level` 分布（W4a 点名未审计项）

在 588 题、1090 个解析值上逐值跑 `explain_v2`：

### 6.1 按类别拆开看，结论比"30.5% 很高"要轻得多

| 类别 | `endpoint` | `chunk_field` | `predicate` | `none` | 合计 |
|---|---|---|---|---|---|
| `multihop` | **464** | 0 | 0 | 1 | 465 |
| `cross_chunk` | 0 | **205** | 0 | 0 | 205 |
| `single_chunk` | 0 | **127** | 0 | 0 | 127 |
| `direct_relation` | 0 | 0 | **89** | **7** | 96 |
| `alias` | **87** | 0 | 0 | **2** | 89 |
| `time_conflict` | 0 | 0 | 0 | **64** | 64 |
| `adversarial` | 0 | 0 | 0 | **32** | 32 |
| `negative_abstain` | 0 | 0 | 0 | **12** | 12 |

三条关键观察：

1. **`chunk_field` 332 个全部来自 `cross_chunk`(205) 与 `single_chunk`(127)** ——
   这两类的答案本来就是**章节名 / 标题**，用 `chunk_field` 见证是**设计如此**，
   不是退化。`cross_chunk` 问的就是章节代号，`single_chunk` 的标题类答案同理。
2. **`none` 118 个里 108 个来自三个结构类**（`time_conflict` 64 + `adversarial` 32 +
   `negative_abstain` 12）。这三类**本来就不打分**（`pass=None`），
   `none` 是正确行为，不是缺陷。
3. **真正需要警惕的只有 9 个**：`direct_relation` 的 7 个 `none` 与 `alias` 的 2 个。

### 6.2 判定

`support_ok` 的严格度**比 W4a 担心的要高**：
- 强见证（`endpoint` + `predicate`）占 **58.8%**；
- 弱见证 `chunk_field` 的 30.5% **集中在两类本来就是章节类答案的题上**；
- 真正可疑的 `none` 只有 9/1090 = **0.83%**。

**但 `evidence` 层使用量为 0 这件事值得记**：它是 `SUPPORT_POLICY` 的兜底层，
一次都没命中说明现有答案的实体名都能在 `endpoint`/`chunk_field` 里找到，
不需要靠子串兜底。这是好事，但也意味着**那条兜底路径实际上未被任何真实样本检验过**。

## 9. 诚实边界

1. **`bridge` 的 holdout 显著性消失，是本轮最需要人复核的一条。**
   它是**组合臂**（bridge + reserve），不是单开 bridge。Δ=+4.10pt（8 题），
   点估计为正、方向一致，但 cluster CI 跨零。**这不等于"bridge 没用"**，
   而是"以 holdout 为确认集、以聚类为口径时，证不出显著"。
2. **`graph_reserve` 只有 dev 显著。** 与历史 p=0.1562 一致，未被推翻。
3. **K4 的绝对判定 FAIL 是环境漂移，不是 cap 的问题。** 已把两个判定分开报。
4. **`witness_level` 的 30.5% `chunk_field` 集中在两类章节题，不是退化**——
   但这条结论依赖"章节类答案用 `chunk_field` 是设计如此"这个判断，
   若你认为它不该这样设计，那 30.5% 就该按退化重读。
5. **`evidence` 层从未命中**（0/1090）。这条兜底路径未被真实样本检验过。
6. **J2 的 A 组只覆盖计划书点名的 2 题**，不是完整 5 题——计划书提到"5 个逆序对"
   但只给出了这 2 题的 F1 数字，其余 3 题未具名，无法逐题重判。
