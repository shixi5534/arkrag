## 现有检查为什么漏掉它们

`identity.is_generic_anchor()` 的判据是「**整个名字就是一个泛称标记**」：

```
完全等于词表里的泛称（MEMBER_SUFFIXES / ORG_SUFFIXES / GENERIC_PERSON_NOUNS）
或「以成员后缀结尾且去掉后缀后是一个泛称/职务词」
```

这个判据刻意不按「以泛称结尾」判，理由是 `凯尔希医生` / `罗德岛制药公司`
是全名归并、必须放行——按结尾判会把契约自己举的例子打成拒绝。

但真实数据里的泛称锚点是**「修饰语 + 职务词」**形态，不是「整个名字就是泛称」：

| 别名 | 规范名 | 为什么漏 |
|---|---|---|
| `罗德岛工程干员` | 克里斯 | 去掉 `干员` 得 `罗德岛工程`，不在词表里 |
| `拍摄队长` | 南希 | 去掉 `队长` 得 `拍摄`，不在词表里 |
| `冷静的杀手` | 博尔托洛蒂 | 去掉 `杀手` 得 `冷静的`，不在词表里 |
| `二队长` | 歌蕾蒂娅 | 去掉 `队长` 得 `二`，单字，不构成泛称词 |

`identity.py:329-330` 已如实记了 `人事干员` 这个已知缺口，但当时判断是
「`人事` 不在词表里，本模块不许自造第二份词表」——实测说明这个缺口不是个例，
而是这一类形态的普遍情况。

## 能区分的结构性判据（已实测）

不靠词表，靠三个前置条件：

```python
def is_generic_anchor_by_shape(alias: str, canonical: str) -> bool:
    # 1) 别名整体以成员/组织后缀结尾（且不是后缀本身）
    if not any(alias.endswith(s) and len(alias) > len(s) for s in SUFFIXES):
        return False
    # 2) 互相包含 -> 是全名归并（凯尔希医生 / 罗德岛制药公司 / …自治州住宅管理委员会）
    if canonical.startswith(alias) or alias.startswith(canonical):
        return False
    if canonical.endswith(alias) or alias.endswith(canonical):
        return False
    # 3) 共享首字 -> 姓氏/缩写式别名（魏大长官 / 魏彦吾、麟长官 / 麟青砚）
    if canonical[0] == alias[0]:
        return False
    return True
```

三条前置各自挡掉一类误伤，实测数据：

| 判据版本 | 命中 | 占 1,605 对的比例 | 误伤 |
|---|---|---|---|
| 只看「以泛称后缀结尾」 | 40 | 2.49% | 全名归并（`…自治州住宅管理委员会`）被误拦 |
| + 互不包含 | 30 | 1.87% | 姓氏式别名（`魏大长官`）被误拦 |
| + 共享首字 | **26** | **1.62%** | 抽样未见 |

## 更强的一层证据：这些名字是「无名 NPC 的说话人显示名」

形态判据只能说明"长得像泛称"。真正决定性的证据来自语料本身——
**这 26 个字符串里，有 13 个在 `scenes.jsonl` 里是作为 `speaker` 出现的**，
且几乎从不出现在正文里：

| 别名 | 作 speaker 次数 | 出现在正文次数 |
|---|---|---|
| 罗德岛外勤干员 | 197 | 1 |
| 老练的士兵 | 96 | 0 |
| 落魄商人 | 80 | 0 |
| 拍摄队长 | 75 | 0 |
| 冷静的杀手 | 41 | 0 |
| 精明的商人 | 34 | 1 |
| 黑帮首领 | 24 | 1 |
| 勤快的守卫 | 21 | 0 |
| 严肃的雇佣兵 | 20 | 0 |
| 凶名赫赫的雇佣兵 | 17 | 1 |
| 修整武器的雇佣兵 | 17 | 1 |
| 蛮横的感染者 | 16 | 0 |
| 黑钢情报小组成员 | 12 | 0 |

**这是一个角色属性，不是一个专名。** 剧本用「种族/职业 + 身份描述」给没名字的
路人当显示名（`哥伦比亚士兵`、`女性居民`、`感染者哥哥`、`狱警A` 同理）。
把这种显示名并到某个具名角色名下，等于断言"所有出现在这里的无名士兵都是暴雨"。

剩下 13 个形态相反——只在正文里出现：
`二队长` 29 次、`我的家族` 25、`小工匠` 50、`库兰塔士兵` 7、`随行干员` 7、
`乌比卡研究员` 6、`总公司` 3、`萨卡兹刀术师` 2、`传奇的退役战争术师` 1、
`佣兵刀术师` 1、`金发的研究员` 1。
这些是抽取器从对白里抓的描述性短语（"那个库兰塔士兵"）当成了别名，
同属误并，但机理不同——前者是显示名被当专名，后者是叙述性描述被当专名。

## 联网核实（PRTS 官方 wiki）

按用户 2026-10-31 授权「无法确定游戏中角色关系或相似情况可以联网」，
对最典型的一例做了核实：

**`暴雨`（Heavyrain）** —— [PRTS 干员页](https://prts.wiki/w/%E6%9A%B4%E9%9B%A8)：
- `|种族=库兰塔`（档案区 `人员档案set` 字段）
- `|职业=重装`，分支 `铁卫`
- 客观履历：**「前萨尔贡某王酋麾下士兵」**

所以 `库兰塔士兵` 作为「种族 + 职业」的描述**对暴雨本人是成立的**——
这正是误并难以靠人工肉眼发现的原因：描述没错，错在把描述当成了名字。
`二队长` 亦同：`歌蕾蒂娅` 的职务可能是二队长，但「二队长」这个称呼本身
不唯一指向她（任何组织的第二分队队长都可叫二队长）。

**联网核实的边界（必须写清）**：外部资料只用于**判断某条合并是否指同一实体**，
**不得**用作抽取阶段的实体/关系来源。理由是本项目的第一条硬规则
（`prompt.SYSTEM_PROMPT` 第 3 条）明确禁止用游戏设定知识补写剧情事实；
把 wiki 当抽取依据会直接违反它，并让"回答必须有语料内引用"变得不可能。
本节的 wiki 引用只出现在**核查文档**里，不进入任何产物、不进图、不进索引。

## 处置建议（尚未执行）

1. **进 `check_merge` 作为第 3 条判据的加强**，不是替换：原有「整名即泛称」
   判据保留，新增「修饰语 + 职务后缀」形态判据。
2. **这 26 对当前已在图中**，加强判据后重跑会变成 `rejected:generic_anchor`，
   实体数与边数会变。按 K3 纪律，数量变化必须先归因再接受：
   预期实体数 +N（这些泛称别名原本被并进专名，现在要独立成实体或被丢弃），
   边数变化需逐条核对是否有真实关系因此丢失。
3. **不要只看汇总数字就接受**。`施怀雅家族 <- 我的家族` 这类如果其实是正确合并
   （比如剧情里「我的家族」确实指施怀雅家族），加强判据会造成新的误拆。
   26 对需要人工逐条过一遍，这正是计划书「宁可拆多不可错并」的取舍点。

## 与 `docs/决策台账.md` D-24 的关系

D-24 记录的是**别名链式误并**（`凯尔希` 并查集组塞了 32 人），根因是
`merge_names` 不判「被多方主张」，修法是 `ambiguous_aliases` + 拒绝分支。
本节记录的是**另一类**误并：不是"名字被多方主张"，而是「泛称短语被当成专名别名」。
两者都靠 `check_merge` 拦，但判据完全不同，不能互相替代。

D-23 记过「职位泛称并合只能申报：泛称锚点吸收专名 10 例、专名吸收角色式别名 71 例」——
那 10 例是**只申报**的旧口径。本节给的 26 对是**能当门拦**的新判据，
比"申报"进一步，但落地前需要上面第 3 点的人工核对。
