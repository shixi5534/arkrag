## 三、我怎么在不改 src 的前提下拿到中间量（核心手法）

这是本轮最可复用的部分。三个技巧，全部零侵入。

### 3.1 技巧一：跑两档 `max_claims` 拿"未截断的完整 claim 列表"

`answer.py` 的常量 `MAX_CLAIMS = 8`【代码】，但 `ExtractiveAnswerer.__init__` 接受 `max_claims` 参数并存在实例上。所以：

```python
pipe["answerer"].max_claims = 8      # 生产档
res8 = pipeline.ask_once(pipe, q)
pipe["answerer"].max_claims = 999    # 全量档 → 答案正文逐条就是未截断的全部 claim
resN = pipeline.ask_once(pipe, q)
```

### 3.2 技巧二：用 staticmethod 打桩抓"截断后的 claim 对象"

纯靠 999 档只能拿到**文本**，拿不到 `focus_tier / support_count / unit_score / assertion_id` 这些结构。办法是找一个「截断之后必定被调用、且只被调用一次」的钩子：

`answer.py:803` → `conflicts = self._same_scene_conflicts(accepted)`，而 `_same_scene_conflicts` 定义在 `answer.py:879-880` 是 `@staticmethod`。**它在 `accepted = accepted[:max_claims]` 之后才被调用**，所以收到的正是截断后的列表。

```python
from arkrag import answer as answer_mod
_orig = answer_mod.ExtractiveAnswerer.__dict__["_same_scene_conflicts"].__func__
_captured = {}
def _spy(claims):
    _captured["claims"] = [dict(c) for c in claims]
    return _orig(claims)
answer_mod.ExtractiveAnswerer._same_scene_conflicts = staticmethod(_spy)
```

> **坑**：不能写 `answer_mod.ExtractiveAnswerer._same_scene_conflicts.__func__` —— 通过 `staticmethod` 描述符取出来**已经是普通 function**，没有 `__func__`，会 `AttributeError`。必须走 `__dict__[...]` 拿原始 staticmethod 对象再 `.__func__`。

### 3.3 技巧三：用"最小判过前缀"把「截断」变成可计算量

对每道题，把 999 档的 claim 序列按顺序取前缀 `seq[:k]`、拼成答案、过 `judge_answer`，找最小的 k 使判过：

- `n_cur` = **保持当前 `focus_tier` 排序**时的最小 k
- `n_alt` = **去掉 focus_tier、改按 `(-support_count, -unit_score, assertion_id)` 排序**时的最小 k

这两个数把「MAX_CLAIMS 截断」问题变成了纯比较：
- `n_cur ≤ 8` → 本来就该过（若没过，是别的原因）
- `n_cur > 8` 且 `n_alt ≤ 8` → **纯排序问题**（→ 我定义的 C 桶）
- `n_cur > 8` 且 `n_alt > 8` → **要更多条**（→ B 桶），且 `n_cur` 就是所需的 N 门槛

**这个做法后来被真重跑完全验证**：`n_cur ≤ 12` 的题数 = 真重跑 `MAX_CLAIMS=12` 的通过数（dev 9），`n_cur ≤ 20` = 20 档的 12。逐档吻合（8/9/12/12/12）。→ **前缀推断是可信的，不必每题重跑。**

### 3.4 落盘结构 `tmp_dg_out_{split}.json`

每题一行，字段（**注意 claim 用的是短键，这是我自己定的，不是 src 的**）：

```
qid cat split q gold golds gold_chapters anchors need_abstain
ans8 judge8 ansN judgeN n_claims claims[] n_cur n_alt
qa_cands n_hits hit_ids
ctx[]{cid, ch, tokens, g, anc, src[]}

```

其中 `claims[]` 元素是 **`{"i","s","p","o","tier","sup","us","aid","cid","g","a"}`** —— 短键！
`body(c)` 必须写 `f'{c["s"]}{c["p"]}{c["o"]}'`。**我因为写成 `c["subject"]` 白白 debug 了一轮 `KeyError: 'subject'`。**

## 四、系统机制：代码里实际在跑的东西

### 4.1 判据全貌（`src/arkrag/judge.py`，251 行，唯一实现）

```python
judge_answer(category, answer_text, item, *, question=None, chapter_texts=None)
    -> {"pass": bool | None, "reason": str}
```

**归一化**：`_norm()` 做 NFKC + strip，所有字面比较都过这一道。

**锚点**：`_ANCHOR_RE = 「([^」]{1,30})」`，按出现顺序去重。【代码，已验运行时值】
**句子**：按 `。` 切（`_SENTENCE_SPLIT = "。"`）。
**章节切分**：`[、,，/／\s]+`（六种分隔符，因为 `acceptable_answers` 里全出现过）。

| 类别 | 判据 | 拒绝时的 reason（我按这些分桶） |
|---|---|---|
| `single_chunk` / `alias` | 答案含 `answer` 或任一 `acceptable_answers` | `gold_in_answer` / `gold_absent` / `no_gold` |
| `cross_chunk` | 见下方分支序 | `chapter_set_equal`（**pass**）/ `chapter_set_missing` / `extra_chapters_unverified` / `no_entity_to_verify_extra` / `extra_chapter_does_not_mention_entity` / `extra_chapters_outnumber_gold` / `extra_chapters_all_real_and_bounded`（**pass**） |
| `direct_relation` | **某一句**同时含**全部**锚点 + gold | `one_claim_all_anchors_and_gold`（**pass**）/ `no_single_claim_with_all_anchors` |
| `multihop` | gold 与**每一个**锚点**各自**有一条句共现；且 gold 本身不是锚点 | `gold_linked_to_every_anchor`（**pass**）/ `no_claim_links_gold_to_any_anchor` / `gold_not_linked_to_every_anchor` / `gold_is_an_anchor` |
| `time_conflict` / `negative_abstain` / `adversarial` | 不判分，返回 `pass=None, reason="structural:not_supported"` | 结构类，**剔出分母** |

**`cross_chunk` 的分支顺序很重要**（决定了 reason 分布，也就是我分桶的依据）：
```
got == want                      → chapter_set_equal (PASS)
not (want ⊆ got)                 → chapter_set_missing (FAIL)
extra = got - want
chapter_texts is None            → extra_chapters_unverified (FAIL)
name = 首个不在 want 里的锚点；无 → no_entity_to_verify_extra (FAIL)
任一 extra 章节正文不含 name      → extra_chapter_does_not_mention_entity (FAIL)
len(extra) > len(want)           → extra_chapters_outnumber_gold (FAIL)
否则                              → extra_chapters_all_real_and_bounded (PASS)
```
→ **`pass` 只可能来自 `chapter_set_equal` 或 `extra_chapters_all_real_and_bounded`**，这两个 reason 的数量之和**必须恒等于** pass 数。我在三个 split 上都验证了这个恒等式成立（dev 11+8=19、holdout 6+7=13、clean 3+5=8）。

**`chapter_texts` 参数据此重要**：不传时 `cross_chunk` 只能做集合相等（reason 会写 `extra_chapters_unverified`）。我的 `chapter_texts` 口径 = **整世代 494 章的 `{chapter: 全部块正文 \n 拼接}`**。

### 4.2 答案生成（`src/arkrag/answer.py`，969 行）

**运行时常量（已验）**：

| 常量 | 值 | 作用 |
|---|---|---|
| `MAX_CLAIMS` | **8** | 答案最多几条事实 |
| `MIN_EVIDENCE_CHARS` | **4** | 引用证据最短长度 |
| `DEFAULT_MIN_TOP_SCORE` | **0.05** | 低于此拒答 |
| `CITATION_WHOLE_LINE` | **False** | 引用粒度：断言 span（非整行） |
| `TITLE_ANSWER_PATH` | **True** | 标题通路（问"出处标题"时直接答 `unit["title"]`） |
| `CHAPTER_ANSWER_PATH` | **True** | 章节通路（问"章节代号"时答 `unit["chapter"]` 集合） |
| `TITLE_TRIGGERS` | 请给出该块的标题 / 请回答该段的标题 / 出自哪个文本块 / 来自哪一段剧情 | 标题通路触发词 |
| `CHAPTER_TRIGGERS` | `("章节代号",)` | 章节通路触发词 |

**`answer()` 的执行顺序（每一步都是失效模式）**：
```
1. 三道拒答闸
   a. query_analysis["should_answer"] is False → 拒答
   b. units 为空                                → no_context_units
   c. top_score < 0.05                          → insufficient_retrieval
2. TITLE_ANSWER_PATH 命中 → 直接返回 title（绕过 claim 机制、MAX_CLAIMS、逐行支撑、接地判据）
3. CHAPTER_ANSWER_PATH 命中 → 直接返回章节集合（同上绕过）
4. claim 机制：
   候选 = 所有 unit["assertions"]
   ├ 判据1：无 evidence span            → dropped_no_citation
   ├ 判据2：_claim_supported_by_line 失败（证据整行不含任一端点名）→ dropped_unsupported
   ├ 判据4：端点不在 context_names       → dropped_ungrounded
   ├ focus_tier 排序 → 按三元组去重 → 截断到 MAX_CLAIMS
   └ 判据5：_same_scene_conflicts（只记 warnings，不删）
5. 答案正文 = 逐条 f"{subject}{predicate}{object}。" 拼接
```

**`focus_tier` 的真实逻辑**（排序判据，**不是过滤器**）：
```python
focus_names = {c["name"] for c in query_analysis["entity_candidates"]}
tier = 0 if 两端都是 focus_names     # 问的正是它们之间的关系
       1 if 一端是
       2 if 都不是                    # 只在上面两档凑不满时才被陈述
sort key = (focus_tier, -support_count, -unit_score, assertion_id)
```

**`_chapter_answer()` 的真实判据**（`nh >= 1`）：
> 某章节进答案 ⟺ 该章节下有**至少一个** unit 的**正文**含**焦点实体名**（`entity_candidates[:2]` 的 name）。

注意它**只读 `unit["chapter"]` 字段**，绝不截 `chunk_id` 路径（路径第二段是 `main`，字段值是 `main_ep14`）。引用取每章第一块里第一条 ≥4 字且含焦点名的行。

**`_title_answer()`**：用问句里 ≥4 字的 `「」` 引文当**定位键**，在 units 里找含该引文行的块，**要求命中块的 title 唯一**（`len(titles) != 1` 就返回 None），答案只能取 `unit["title"]`。

### 5.6 `direct_relation` 判据：单句 + 全部锚点

这条判据要求「**一条**句同时含**全部**锚点 + gold」。所以：
- 我不能用「把 A—gold 一句、gold—B 一句」的拼法（那是 multihop 的判据）
- 而图上 A、B 之间存在**多个**谓词（dev 谓词数分布 `{1:20, 2:9, 3:9, 4:7, 5:4, 6:3, 7:1, 8:2, 11:1, 14:1}`），**必须全部并列写出来**才能保证 gold 在其中一句

**我在这里走过一次错路**：第一版 `tmp_dg_45_paths.py` 是"优先取谓词恰为 gold 的断言"——那是**偷看答案**，导致 48 题被破坏。正确做法是 `tmp_dg_47_dr_honest.py`：**不预设哪个是答案，把图上 A—B 的全部谓词各写一句**。诚实版 57/57 判过、破坏 0。

> 教训：**任何"按 gold 选分支"的脚本，测出来的都是判据的上界而不是系统的可达性。** 判断一个干预值不值得做，必须让脚本在不知道 gold 的情况下选。

### 5.7 `cross_chunk` 全图口径 C2 单用会**丢题**

C2（该章任一块正文含焦点名）单用：dev 25（+6），但**丢了 3 道本来通过的题**（`q-cx-000020`、`q-cx-000027`、`q-cx-900018`）。holdout 丢 2 道。
原因：C2 找到的章节更多，章节数暴涨触发 `extra_chapters_outnumber_gold`。
→ **必须 C0 ∪ C2 取并集**（dev +9、holdout +6、clean +4）才算真实收益。
**这就是为什么"净增"和"单口径 pass 数"是两个不同的东西**，报数必须报并集。

### 5.8 「两跳 A—X—B」图论上存在，判据上零收益

我特意把 S2（X 邻 A、B 在 X 的 ≤2 跳内，X 非一跳公共邻居）单独枚举了，结论是：
- gold 只在 S2 不在 S1 的题 = **0/0/0**（三个 split）
- S2 里的 X 能拼出「X 与 B 同句原文」的 = **0/0/0**

原因：`multihop` 判据要求 gold 与**每个**锚点**分别同句共现**。两跳路径里的 X 只与一侧有直接断言，**发不出另一侧的同句原文**。
→ **「图论可达」≠「判据可满足」。** 这是本轮最重要的方法论教训之一。

### 5.9 `clean` 不是独立抽样

`clean` = holdout 里不在 gold-v1 的题。**它是 holdout 的子集**，不是第三个独立样本。报告里 clean 只作一致性佐证，不作独立证据。而且实测三个 split 的**可判类别占比完全相同**（single 26.7% / alias 20.0% / dr 20.0% / mh 20.0% / cx 13.3%），说明是**严格同分布分层抽样** —— 这才是三个数字接近（69.47 / 67.69 / 69.17）的真正原因。

## 六、核心机制结论（我认为最值得记住的三条）

### 6.1 claim 句恒为二元 → multihop 的 A 桶是形态宿命，不是 bug

**实测**：所有 claim 句的端点数**恒为 2**（dev 866 条 / holdout 667 / clean 387，分布 `{2: N}` 无其他值）【`tmp_dg_A0_facts.py`】。

因为答案正文是 `f"{subject}{predicate}{object}。"` 逐条拼接 —— **一个句号句 = 一条二元断言 = 两个实体名**。
而 `multihop` 判据要「gold 与每个锚点分别同句共现」= 至少两句：`gold+A`、`gold+B`。
claim 只能提供"上下文里已抽取的二元断言"。**当 `gold—A`、`gold—B` 这两条断言没进上下文时，任何组合都拼不出合规答案。**

A 桶（dev 35 / holdout 25 / clean 14 题）= 「gold 在 claim 里，但没有任何 claim 句同时含 gold 与任一锚点」。
**实测：A 桶 35/25/14 题中，"存在一条 claim 同时含 gold + 全部锚点"的 = 0/0/0。**

→ **结论：multihop 卡的不是检索、不是排序、不是 MAX_CLAIMS，是「答案形态只允许二元句」+「gold 的两条邻接断言没被喂进上下文」。** 后者正是桥接通路要解决的。

### 6.2 桥接通路：96 道题**全部**有公共邻居且 gold 在其中，且**全部**能发可校验引用

这是本次最重要的数字【实测 `tmp_dg_24_bridge_q2.py` / `tmp_dg_95_bridge_perq.py`】：

| 指标 | dev (57) | holdout (39) | clean (24) |
|---|---|---|---|
| gold ∈ 一跳公共邻居候选集 | **57** | **39** | **24** |
| 两侧都有偏移可校验断言（CITE_OK） | **57** | **39** | **24** |
| 公共邻居唯一 | 25 | 10 | 6 |
| 唯一且 == gold | **25** | **10** | **6** |
| 候选 >1 且 gold ∈（需排序） | 32 | 29 | 18 |

**"X 与 A 共现一句 + X 与 B 共现一句"的原文真实存在（100%）**，因为答案句直接由 assertion 的 `subject+predicate+object` 构成，而 `text[start:end] == evidence_text` 已验证 20,000 抽样 0 失败。
→ **桥接不是编句子、不是放宽判据，它是把语料里已有的两句原文取出来拼进答案。**

**8 个候选选取策略的实测**（真拼真判）：

| 策略 | dev pass（净增） | holdout | clean |
|---|---|---|---|
| `unique_only` | 25（+17） | 10（+3） | 6（+1） |
| `unique_or_dominant` | 39（+31） | 24（+17） | 13（+8） |
| `top1_if_sup>=4` | 50（+42） | 31（+24） | 19（+14） |
| `top1_if_sup>=8` | 38（+30） | 29（+22） | 18（+13） |
| `all_candidates_sup` | 50（+42） | 31（+24） | 19（+14） |
| `all_candidates_relkinds` | 48（+40） | 27（+20） | 15（+10） |
| `all_candidates_degree` | 35（+27） | 16（+9） | 10（+5） |
| **`top2_both_sup`** | **56（+48）** | **38（+31）** | **23（+18）** |

排序键等价性：`assert_count` ≡ `support_sum`（同一批候选上等价，推荐后者更省算）。

**桥接是生产档的严格超集**：通过题的桥接状态 dev 8/8、holdout 7/7、clean 5/5 全部也过；桶×桥接交叉显示 E/B/A 桶几乎全被覆盖，**只有 3 道题救不回**（dev `q-mh-900034`；holdout 与 clean 均为 `q-mh-900002`）。

### 6.3 cross_chunk 的 missing 100% 是检索召回，不是判据

**根因三桶（章节级，互斥穷尽）**：

| 桶 | dev | holdout | clean |
|---|---|---|---|
| ① 该章压根没进上下文 | **23 (100%)** | **16 (100%)** | **10 (100%)** |
| ② 进了但单元正文不含焦点实体名 | 0 | 0 | 0 |
| ③ 进了且含实体但被别的约束挡掉 | 0 | 0 | 0 |

**决定性反证**：把 `nh>=1` 完全放开（直接交出 ctx 全部章节、不查正文含名），实测整体只过 dev 6/38、holdout 2/26、clean 1/16；**missing 题救回率 = dev 0/16、holdout 0/12、clean 0/7（全部为 0）**。
→ **放宽判据 0 收益。** 缺的章节**压根不在上下文里**，放宽"该章下的单元要含焦点实体"这个条件，不可能凭空造出没进上下文的章节。
别名口径兜底（把焦点实体的全部别名一起查）也**补 0 章**。
