## 1. 攻击点 1：判据是不是在给答案找台阶

### 1.1 分题型判据的宽严实测（不是推理，是计数器）

我在 `judge_current` 之外又实现了三套判据，同一批答案重算（dev 285 可判，五臂 `c5_6000 / c5_12000 / c12_6000 / c12_12000 / c12_40000`）：

| 判据 | 定义 | 五臂通过数（/285） |
|---|---|---|
| `current` | 现行分题型 | 191 / 206 / 203 / **225** / 232 |
| `multihop_all_anchors` | multihop 改"全部锚点" | 166 / 178 / 167 / 183 / 187 |
| `exact` | claim 必须**等于** gold | 114 / 127 / 115 / 130 / 135 |
| `strict_anchored` | gold claim 还需带 ≥1 问句锚点 | 76 / 84 / 91 / 101 / 105 |

**结论：判据确实宽严不一，而且不是均匀宽严，是"专门对两类放宽"。** 逐类拆开看：

| cat | n | current（五臂） | exact（五臂） | 差 |
|---|---|---|---|---|
| single_chunk | 76 | 61 69 61 69 69 | **61 69 61 69 69** | 完全相同 |
| direct_relation | 57 | 41 47 42 50 52 | **41 47 42 50 52** | 完全相同 |

| multihop | 57 | 25 28 36 42 45 | **0 0 0 0 0** | 全灭 |

即：`current` 的"含 gold 串"宽松只对 **alias + multihop** 生效，其余三类在严格判据下与现行判据**一字不差**。alias/multihop 在 exact 下归零说明 exact 对它们过严（gold 是短语，答案必然还带别的东西），但这也反证：**现行判据对这两类的宽容是没有独立校验的**。

### 1.3 `single_chunk` / `alias` 的「gold 串出现在任一处」是否过松

## 2. 攻击点 2：65 题剔除是否合法

### 2.1 先纠正一个措辞错误

这 65 题在判据里的返回值是 **`None`（拒判），不是 `False`（答错）**。time_conflict 38×3 臂全 None、adversarial 19×3、negative_abstain 8×3。它们的答案里 **gold 串一次都没出现**（0/64、0/32、0/12），因为答案全是「A谓词B。」三元组，不可能撞上「时序演进」「否」或 adversarial 的长句。

所以 D 说"全部 0 通过、结构上做不到"——**准确说法是"回答器根本不产生这类形态的答案，判据无法适用"**。这两件事在统计上的处理不同：前者可以剔除，后者应记为"通路缺失"。

### 2.2 可达性实测（S20，直接跑真 pipeline）

用 `build_pipeline(load_generation("g-20261103T132152Z-06a741"), top_k=20, graph_depth=1)`，budget=12000、max_claims=12，对 dev 65 题逐题跑 `ask_once`：

| 类别 | n | 所需判别信号已在管线输出里 | 明细 |
|---|---|---|---|
| time_conflict | 38 | **16（42.1%）** | 答案里出现互斥谓词对 18 题，其中该对**跨不同 doc**（正是 gold 要的"剧情演进"）16 题，同 doc 4 题；answerer 自己的 `stats["conflicts"]` 只触发 3/38 |
| negative_abstain | 8 | **8（100%）** | `negated_hint` 置位 8/8；问句「」引文已进入上下文 8/8；两者同时满足 8/8 |

### 2.3 代码级证据：结论"做不到"被 `_same_scene_conflicts` 自己反驳

`src/arkrag/answer.py:853`：

```python
def _same_scene_conflicts(claims):
    ...
    if a["doc_id"] != b["doc_id"]:
        continue   # 不同 doc = 不同场景，属剧情演进，不算冲突
```

它**已经算出了 gold 要的结论**（不同 doc → 剧情演进，不是矛盾），但调用点 `answer.py:776` 的结果只写进 warnings：

```python
warnings.append(f"冲突未合并：{item['detail']}（同一场景内互斥，须人工判定，不写成一句确定的话）")
answer_text += "（注：以上关系存在互斥记录，见 warnings，不作单一结论。）"
```

**没有任何分支把这句话写成答案。** 缺的是一条 `if conflicts: answer_text = "时序演进"` 的分支，不是"结构上做不到"。

另外两条通路的可行性：
- `_chapter_answer`（`answer.py:149`）已经示范了"用 `query_analysis["entity_candidates"]` + unit 字段组合出新答案形态"这个模式，adversarial 需要的实体类型同样可从 `entity_candidates` 或 graph 取。
- `_title_answer`（`answer.py:238`）证明"在 `answer()` 主流程之外加一条 trigger-gated 的特判通路口"是既有工程习惯。

### 2.4 但 D 有一个我没能驳倒的地方（必须写出来）

**这 65 题的 gold 本身是退化的。** time_conflict 38 题的可接受答案只有 4 个语义槽位、与题目内容无关（例：`["不是矛盾，是剧情先后变化", "先后出现隶属与背叛，不是矛盾", "剧情阶段变化，两条都成立", "时序演进"]`），我实测**一个常量「时序演进」就能拿 38/38**；negative_abstain 有 gold 的 8 题，常量「否」拿 **8/8**。

这说明：**即使写了通路，这 65 题也不是在测"回答能力"，而是在测"是否输出固定串"。** 所以：
- 把它们从分母剔除 → 掩盖失分，不合法；
- 把它们计入分母并写常量通路 → 虚增 65 题，同样不合法；
- **正确做法是把这 65 题重写（gold 必须与题面内容绑定），在此之前单列、不参与任何比率。**

### 2.5 裁决

**D 不成立。** 三处硬伤：
1. "结构上做不到"被 S20 证伪（43/65 的信号已在管线里，其中 16 题的结论 `_same_scene_conflicts` 已经算出来了）；
2. "全 0 通过"是 None（判据不适用）被当成 False（答错），措辞掩盖了机制；
3. 剔除分母会让所有分数凭空抬高 **11~15pt**（§3.1），这不只是记账问题。

## 3. 攻击点 3：holdout 污染与 clean holdout 的统计功效

| holdout | c12_12000 | 149/238 = **62.61%** | 149/195 = **76.41%** |

**A 报的 78.95% / 76.41% / 80.83% 全是可判分母口径。真实生产口径（全分母）是 64.29% / 62.61% / 63.19%。** 配对 Δ 不受影响（两臂同为 0），但绝对水平被人为抬高 11~15pt，读者若把它当"系统准确率"就会误判。

### 3.2 污染数核实：用户说的 100 是对的，我先前报 94 也是对的（口径不同）

我自己读了 `data/goldset/gold-v1.json`（320 题）与 `gold-v2.json`（640 题，dev 380 / holdout 260）：

- gold-v1 的 320 个 question_id **全部**出现在 gold-v2 里（overlap 320，缺失 0）
- holdout 260 题里，**question_id 也在 gold-v1 里的 = 100**（← 用户的口径，正确）
- 若先限定"有 gold_chunk_ids 的 238 题"，则其中与 v1 重叠 = **94**
- clean holdout = 160 题，有 gold 144 题，可判 120 题 —— **与 A 给的分母完全吻合，无造假**
- v2 的 `origin` 字段计数：`{v1: 320, new: 320}`；holdout 内部 `{v1: 100, new: 160}`

**结论：污染数 100 无误，clean holdout 的大小也无误。**

### 3.3 污染是否造成虚高——实测为"否"

| 臂 | v1 携带的 holdout 子集（n=75） | clean 子集（n=120） | 差 |
|---|---|---|---|
| c5_6000 | 52/75 = 69.33% | 85/120 = 70.83% | **−1.50pt** |
| c12_6000 | 52/75 = 69.33% | 88/120 = 73.33% | **−4.00pt** |
| c12_12000 | 58/75 = 77.33% | 91/120 = 75.83% | **+1.50pt** |

类别构成也基本同比例（v1 携带：sc 20 / al 15 / dr 15 / mh 15 / cx 10；clean：sc 32 / al 24 / dr 24 / mh 24 / cx 16）。

**这条攻击线不成立：污染没有虚高任何一档，clean 子集不比污染子集更简单。**

### 3.4 clean holdout 的 CI 宽不宽——用功效分析回答

clean holdout n=120，两臂不一致的题（discordant）只有 12 题（10.0%）和 11 题（9.2%）。我做配对功效模拟（600 次重抽，seed 7）：

| 真实效应 | c5_6000→c12_12000 的检验功效 | c12_6000→c12_12000 的检验功效 |
|---|---|---|
| +2pt | 10.3% | 8.0% |
| +3pt | 21.8% | 21.8% |
| **+5pt**（A 报的效应量） | **46.0%** | **50.2%** |
| +8pt | 93.2% | 96.0% |

**结论：clean holdout 单独看，在 A 自己报的 +5pt 效应量下只有约 46% 的功效（相当于掷硬币）。它既不能确认 +5pt，也不能排除 +5pt。所以"clean holdout 的 CI 含 0 所以不显著"与"clean holdout 显著所以可以接生产"两种读法都不成立——这个子集的样本量根本不足以做这个判断。**

精确符号检验（不看 bootstrap 实现，只看不一致对的方向）：

| subset | 对照 | 不一致对数占比 | +/− | 符号检验 p |
|---|---|---|---|---|
| dev | c5_6000→c12_12000 | 15.4% | +39/−5 | **0.0000** |
| dev | c12_6000→c12_12000 | 12.6% | +29/−7 | **0.0003** |
| holdout | c5_6000→c12_12000 | 10.3% | +16/−4 | **0.0118** |
| holdout | c12_6000→c12_12000 | 9.7% | +14/−5 | 0.0636 |
| clean | c5_6000→c12_12000 | 10.0% | +9/−3 | 0.1460 |
| clean | c12_6000→c12_12000 | 9.2% | +7/−4 | 0.5488 |

### 3.5 A 的 clean holdout 数字是怎么来的（已锁死）

同一个 clean holdout 120 题，从 `data/diag_crossmode_holdout.json` 直读：

| 臂 | sup 判据 | eq 判据 |
|---|---|---|
| c5_6000 | **87/120 = 72.50%** | 85/120 = 70.83% |
| c12_6000 | 90/120 = 75.00% | 88/120 = 73.33% |
| c12_12000 | **97/120 = 80.83%** | 91/120 = 75.83% |
| c12_40000 | 108/120 = 90.00% | 99/120 = 82.50% |

**A 写的「clean holdout 72.50% → 80.83%」正是 sup 判据的两格，不是 A 自己声明的"cross_chunk 用集合相等"。** 同一 120 题在 eq 下是 70.83% → 75.83%。这是**判据混用**：dev/holdout 主表用 eq，clean holdout 那一行偷换成 sup。

同理，A 的 dev「67.02%→78.95%」把 **c5_6000** 与 **c12_12000** 配对（同时改了 claims 和 budget 两个变量），而紧跟其后的「Δ=+7.72 CI[+3.51,+11.93]」是 **c12_6000→c12_12000** 这一对照。**点估计和 CI 用的是不同基线。**

### 3.6 裁决（攻击点 3）

- 污染数 100：**复现，无误**；
- clean holdout 大小与可判 120：**复现，无误**；
- 污染导致虚高：**不成立**（实测无虚高，甚至略低）；
- **clean holdout 的 CI 确实宽到不能支撑生产决定**——但不是因为污染，而是因为 n=120、只有 12 对不一致、功效 46%。

## 7. 若只能保留一条改动，该保留哪条

**保留 A：`max_context_tokens` 6000 → 12000。**

理由按强度排序：

1. **它是唯一一条"换什么都成立"的改动。** 换判据（current / exact / best_effort / defensible 四套）、换子集（dev / holdout / clean holdout）、换对照臂（c5_6000 或 c12_6000），增益都在，且 defensible 判据下 dev **+27/−1**、holdout **+14/−3**、clean **+8/−3**，退步极少。B 的效应量在最严判据下只有 **2~4 题**，且 dev 侧证据是 multihop 一跳假过堆出来的（§6.2），本质上不可定论。C 是记账问题不是改动。D 是测量口径问题不是改动。
2. **延迟代价实测为零。** 12000 档端到端 p50 82.4ms vs 6000 档 83.4ms（§4.3），40000 档也只 +5ms。这是一次"涨 11pt 准确率、不涨延迟"的改动。
3. **它把问题暴露得最彻底。** 一旦 budget 提到 12000，cross_chunk 的多列问题和 multihop 的一跳问题都会被放大（eq 判据错杀 5→18 题），从而逼着判据必须修——这是好事，不是坏事。

**但保留 A 有三个前置条件，缺一不可：**

- **(a) 先改判据，再报数字。** cross_chunk 从 `eq` 换成"超集 + 所有额外章节真实提及"（§5.5），multihop 从「≥1 锚点」换成「gold 与每个锚点各自共现」（§1.2）。否则 A 报的 cross_chunk 12/11/12/11/14 是假退步，multihop 25/28/36/42/45 是假通过。
- **(b) 改掉陈述里的三处口径混用。** clean holdout 的 72.50→80.83 必须写成 sup 判据（或改报 eq 的 70.83→75.83）；dev 的 67.02→78.95 与 Δ=+7.72 必须用同一基线（要么都报 c5_6000→c12_12000 = +11.93，要么都报 c12_6000→c12_12000）；延迟必须报 12000 档实测（§4.3），不能引 40000 档的 149→148。
- **(c) 报绝对水平时同时给全分母。** 78.95% / 76.41% 是"可判分母"，真实生产口径是 64.29% / 62.61%（§3.1）。两个都给，读者才不会误判系统准确率。

**如果只能保留一条改动、且不允许改判据**——那就**一条都别保留**。因为在 `eq` + 「≥1 锚点」这套判据下，A 的 holdout 增益是 +4.62 CI[+0.51,+9.23] p=0.022（clean holdout p=0.221），B 是 p=0.052，两者都在擦边；用擦边证据做生产决定，无论选哪条都是赌。
