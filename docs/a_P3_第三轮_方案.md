## 0. 为什么必须三道闸并列报（本轮判据的核心改动）

Lead 今晚的预算三档生产真跑（`f9f82dc`，dev 350）给出了这条纪律的直接证据：

## 1. 靶子 ① `cross_chunk` 章节包

#### 1.3.1 事后订正（写方案时我不知道这件事，动代码前才查清）

**「+24」是「全图断言」口径，而 `answer()` 在结构上拿不到全图断言索引。**

`ExtractiveAnswerer.answer()` 的签名只有 `(self, question, context, *, generation_id, top_score,
query_analysis, retrieval_stats)`，正文里 `units = list(context.get("units") or [])`，
`context` 只有 `context_digest` / `stats` / `units` 三个键——**没有 retriever 句柄，也没有全图断言**。
所以 §1.2 那条「实体在**断言**里作 subject/object 圈块」的路子在现接入点不可达，除非改
`src/arkrag/pipeline.py` 把断言索引塞进 `context`（那就不是单变量了，且会动评测路径）。

实测（同一批 38 题、同一份 `ask_once` 上下文）三种口径：

| 口径 | 命中 | 可达性 |
|---|---|---|
| 全图断言（Lead `f6fc03c` 的结构量，本方案原定的 24） | **24/38** | 需要全图断言索引；`answer()` 拿不到 |
| 单元口径 · 章节集合精确相等 | **15/38** | 可达（抽象天花板） |
| 单元口径 · 子串（`gold in answer`，即 `answer_hits_gold` 的既有判法） | **13/38** | 可达；**实测实现打满** |

判据网格（单元口径，集合精确相等）：`nh>=1` **12**（`nh` = 该章节下正文含焦点实体名的单元数）、
`nh>=1 AND nu>=1` 12、`nu>=1` 10、`na>=1`（断言端点命中）10、`nboth>=1` 10、`nh>=2` 2、`nh>=3` 0。
**没有任何阈值组合能超过 12**，故取最简单的 `nh>=1`。分离度：多余章节的 `na` 恒 0（20/20），但
**11 个 gold 章节的 `na` 也是 0** ⇒ `na>=1` 会丢 gold；`gold nh` `{1:23,2:14,3:11,4:10,5:4}` 与
`extra nh` `{0:3,1:10,2:3,3:2,4:2}` 重叠 ⇒ `nh` 也分不开 gold 与多余章节。

**⇒ §5.1 的 K1'/K2'（净增 ≥20）在现接入点是够不到的；这个门槛是我按不可达口径定的，错了。
实现按 `nh>=1` 打满 13/38，实测 FAIL，如实上报，不调门槛追认。**

### 1.4 失败形状

1. **答案字符串不等**：若按「上下文单元顺序」拼而不是按块 id 升序，「、」连接结果会与 gold 顺序不符，
   答案判据从 24 掉到个位数。**必须按块 id 升序。**
2. **章节名取到路径第二段**：答案变成 `main`/`memory` 而不是 `main_ep14`/`memory_whitw2`，24 → 7。
3. **取到无关章节**：判据改成「实体在正文出现」，`q-cx-000001`/`q-cx-000004` 这类会多出章节，
   「集合相等」变成「超集」，判据全错。
4. **引用被迫为 0 → 答案被清空**：`src/arkrag/answer.py:298-303` 的 `verify_citations` 规定
   「一条引用都不剩却还有答案正文」就清空答案并改拒答（`abstain_reason="no_valid_citation"`）。
   全 38 题里 3 题（`q-cx-000029`、`q-cx-900018`、`q-cx-900024`）在我草拟的引用规则下拿不到任何引用；
   **其中落在 24 道可兑现题里的只有 1 题（`q-cx-900024`）** ⇒ 若不兜底，可兑现从 **+24 掉到 +23**。
   实现时必须给该题自带引用兜底（取上下文里第一行含问句实体的行）。
5. **拒答题被误答**：24 题里当前 2 题拒答（`q-cx-000004`、`q-cx-900024`）。我逐题查过拒答原因，
   **都是 `no_supported_claim`（claim 层立不住），不是三道拒答闸拒的** —— 两题 `top_score` 分别
   1.5000 / 1.4932（远高于 `min_top_score=0.05`）、`units` 5 / 4。新通路插在三道拒答闸之后，
   **会对它们生效**，两题从拒答转作答。两题 `should_abstain=False`，转作答是好事，但**报告必须单列
   这 2 个题号**并写明「从 `no_supported_claim` 转作答」，不能混在净增里不提。

### 1.5 开关与接入点

新增 `CHAPTER_ANSWER_PATH = False` + 纯函数 `_chapter_answer(question, units, retriever_state)`。

接入点与标题通路**完全同一处**：`src/arkrag/answer.py` 现有标题通路代码是 `:421-450`
（`if TITLE_ANSWER_PATH:` 在 `:426`，未命中记 `{"applied": False}` 在 `:450`）⇒ **新通路插在
`:451` 之后、`:452`「收集候选 claim」之前**，命中即 return。这样三道拒答闸（`:405` `should_answer` /
`:409` 空 units / `:413` `top_score < min_top_score`）在它之前 ⇒ 合法拒答不受影响；claim 生成 /
`MAX_CLAIMS=5` 截断 / `_claim_supported_by_line` / `_claims_are_grounded` 全在它之后 ⇒ 命中时完全
绕过，这是单变量保证。

### 1.6 会不会变成洗牌

**不会，且 churn 判据不适用。** 该通路是纯问句字符串触发 + 块字段读取，**完全不经过 `search`**，
top-20 集合与 `units` 逐题不变 ⇒ 变动集合 = 0，不存在靠改排序凑分的空间。预筛结论：零洗牌风险。

## 2. 靶子 ② `multihop` 共同中间实体

### 2.1 假设

`multihop` 57 道应答题问「从 A 出发经一个中间实体到达 B，中间实体是谁」，当前 `answer_hits_gold = 25/57`。
图里有邻接表，两端点的**共同邻居**就是候选中间实体。

假设：**`neighbors(A) ∩ neighbors(B)`，按两侧边权和取 top1；当候选唯一时直接作答。**

`retriever.adjacency[eid]` 是 **dict**，键 `['out','in']`，元素取 `nb["neighbor_id"]` /
`nb["relation"]` / `nb["weight"]`（同一邻居多边取最大权重）。**必须 `out ∪ in` 并 discard 自身**，
只读 `out` 会漏一半关系。

### 2.2 最小验证方式

一轮真跑 dev 380，只开这条通路，报三道闸。上界已实测（本段）：
- 不加闸：规则答对 42/57、当前已对 25、**救 24、打坏 7**。打坏 7 题：`q-mh-000016`、`000024`、
  `000025`、`000026`、`000047`、`q-mh-900022`、`q-mh-900033`。
- **加闸 G1（`n_cand == 1`，候选唯一）→ 触发 25 题、规则答对 25/25、救 15、打坏 0。**
- G1 救回 15 题：`q-mh-000013`、`000018`、`000020`、`000033`、`000035`、`000036`、`000041`、
  `000044`、`q-mh-900005`、`900006`、`900014`、`900019`、`900021`、`900045`、`900047`。
- 候选数分布：1 个 25 题、2 个 17、3 个 5、4 个 6、5 个 3、6 个 1。

**必读的坑（Lead m04575 亲自踩过，必须写进实现）**：取「」引文实体时，正则**不许加最小长度限制**。
本语料存在**单字实体名**（`W`、`九`、`均`、`年`、`空`）：

| 题号 | 第一个端点 | 第二个端点 |
|---|---|---|
| `q-mh-000015` | 嘉维尔 | **W** |
| `q-mh-000021` | 吽 | 六十七 |
| `q-mh-900001` | **九** | 坎黛拉 |
| `q-mh-900047` | **均** | 监察司 |

用 `re.findall(r"「([^」]{2,})」")` 或 `len(name) >= 2` 会把上面这 4 题的第二个实体**静默排掉**，
结果变成「可解析 53 题、候选唯一 23 题、top1 41/57」——数看着像模型不行，其实是抽取把可救的题扔了
（这 4 题里有 2 题落在唯一候选集，是本靶子最稳的那批）。**必须用 `「([^」]+)」`，长度校验交给
`MIN_EVIDENCE_CHARS` 那条已有阈值，不要在这里另加。**
- 另：`acceptable_answers` 对这些题没有额外命中（严格相等 45 = 含 acceptable 45）⇒ **答案判定用严格
  相等即可，不必展开 `acceptable_answers`**。
- **其他闸全部等价于 G1**：「边际 ≥2.0」「边际 ≥1.5」触发的都是同一 25 题（`n_cand ≥ 2` 的题
  `ratio` 全落在 1.0–1.286，没有一道过 1.5）。**所以「加边际闸」不是独立变量，别当第二变量测。**

### 2.3 预期影响（三道闸逐级报，以题数计）

| 闸 | 变化 | 说明 |
|---|---|---|
| 答案对 | **+15**（122 → 137） | 该类别 25/57 → 40/57，打坏 0 |
| 引用覆盖 | **+0**（63 不变） | `required_in_context = 0/57`，一题涨不了 |
| 正确覆盖 | **+0**（25 不变） | 同上 |

⇒ 这个靶子**只买答案质量**。若报告把它写成「提升引用覆盖」就是方向错了。

### 2.4 失败形状

1. **打坏已对的题**：不加 G1 闸净 +17 但丢 7 题。**G1 是必须项，不是可选优化。**
2. **引用为空导致答案被清空**：实测 G1 的 25 题，中间实体名在上下文正文里**都能定位到行 25/25**
   （救回 15/15 也能）；现状引用条数合计 157、无 0 条引用题、当前 0 拒答 ⇒ 自建引用**可行**，
   不会触发 `answer.py:298-303` 清空分支。**这是「能不能做」的前置证明，不做会白干。**
3. **只读 `out` 不读 `in`**：漏一半邻居，候选集合缩小但正确率未知，属未测偏差。
4. **候选唯一但答案错**：dev 上 25/25 全对，无此类失败；new 批可能有，需真跑确认。

### 2.5 开关

新增 `MIDDLE_ENTITY_PATH = False` + `_middle_entity_answer(question, adjacency, qa)`，接入点同 §1.5，
命中即 return。**与靶子 ① 是两个独立开关，必须分两轮测**，不许一轮开两个。

### 2.6 会不会变成洗牌

**不会，churn 不适用。** 纯图结构 + 问句触发，不经过 `search`，top-20 与 `units` 逐题不变。

### 3.4 必须先回答的质疑：这算不算循环论证

`src/arkrag/goldset.py:468 mine_alias_questions` 的出题逻辑是：取实体的**权威别名**
（`_authoritative_aliases`，即 `review ∈ {auto, approved}`），在实体自己的 chunks 里找**同一块正文
同时含别名与规范名**的块，`evidence = _window_text(chunk["text"], alias)`。

也就是说 **alias 题的 gold 答案本来就来自图里的权威别名表**。用 `alias_index` 作答不是「偷看答案」，
而是**本该如此**：这个类别的定义就是「别名指哪个规范实体」，而图谱里存着这张表。

实测支撑：
- `graph["alias_index"]` 共 **1671 条，恰好等于全部权威别名的总数**（`aliases[].text` 去重同数）；
  `pending_aliases` 562 个里只有 **3** 个混入索引 ⇒ 索引不含系统自己不敢用的判断。
- 57/57 的 `required.evidence` 在块正文里**整行可定位**；57/57 都能被别名路径绕过。

**但报告必须诚实写**：这条通路的价值不是「推理能力」，而是「把图里已有的别名表接进回答链路」。
它提升的是**引用覆盖**，不是答案质量（答案本来就对 52/57）。台账按这个性质记。

### 3.5 失败形状

   **45/57**。**不能加这个约束。**
2. **引用条数爆量**：不加「每块只取第一行」会按行爆炸。限制后新增 171 条、中位 4、最大 5，可控。
3. **触发词太宽**：非标题 274 题里含「」引文的共 158 题，其中 alias 只占 39。若用「原文」「引文」
   这类泛词会吃进其它类别。**只许用两个骨架的固定串。**
4. **循环论证被误当能力提升**：报告写成「alias 类推理能力提升」就是错的，见 §3.4。
5. **拒答 5 题不可兑现**：`q-al-000010`、`000025`、`000028`、`q-al-900019`、`q-al-900047` 当前拒答，

### 3.7 靶子 ④（只分类，不出方案）：`alias` 失败分层
