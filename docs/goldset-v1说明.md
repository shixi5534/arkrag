# Gold Set v1 说明

`data/goldset/gold-v1.json` —— 320 条评测题的机械构造说明、判据、占比与已知局限。

- 生成命令：`py -3 scripts\build_goldset.py --total 320 --seed 20261101 --report data\goldset\gold-v1-report.json`
- 独立复核：`py -3 scripts\audit_goldset.py`（退出码 0）
- 数据源世代：`data/arkrag/generations/g-20261031T035231Z-4eafae/`（schema `ark-rag-3`）
- 语料：`data/arkrag/chunks.jsonl`（13,786 块）
- 图：`entities` 6,582 / `edges` 28,625 / `assertions.jsonl` 62,910 行 / 邻接 5,728 个实体
- schema 版本 `ark-goldset-1`，seed `20261101`

## 一、为什么机械构造不等于「自证」

这是本文件最需要解释的一点。

「机器出题、机器判分」通常有一个致命问题：出题程序与判分程序共享同一个错误假设时，
评测会稳定地给出满分，而这个满分不说明任何事。F3 的需求原文要求「双人复核」「不接受
答案对但引用错」，正是因为肉眼看不出这类错。

本 Gold Set 用三层约束把这个风险压到可接受范围：

1. **答案锚在一手语料上，不锚在图的主张上。**
   每条题的 `required_citations` 都给出 `(chunk_id, evidence)`，`evidence` 可以
   用 `str.find` 在 `chunks.jsonl` 对应块的 `text` 里逐字定位。判分不依赖图说了什么，
   而依赖原文写了什么。图错了不改变答案的正确性——只改变「这题难不难」。

2. **两条独立的实现路径互相校验。**
   `src/arkrag/goldset.py::validate_gold_item` 是产品的一部分，随构建运行；
   `scripts/audit_goldset.py` 是外部审计，**刻意不 import goldset 的任何挖掘或校验
   函数**，按类别把每条答案重新对回 `chunks.jsonl` / `graph.json` / `assertions.jsonl`。
   两条路径由不同假设驱动，同时对错的概率远低于一条路径自证。审计实际抓到过 3 个
   产品校验器漏掉的缺陷（见第五节）。

3. **出题判据是「可机检的事实形态」，不是「模型认为有信息量」。**
   例如直接关系题要求 `support_count >= 2` 且 `independent_scene_count >= 2`——同一
   关系在两个互不相同的场景里被独立观察到。这是语料统计事实，不是模型判断。

仍然存在的自证风险，如实列出：分类体系（八类）与判据阈值是本项目自己定的；评测的
是「对本语料的检索与推理能力」，不评测「对《明日方舟》世界观的常识」。这两点无法靠
机械手段消除，只能靠人工复核（见第六节）。

## 二、八类挖掘判据

全部实现于 `src/arkrag/goldset.py`，模板集中在模块级 `TEMPLATES` 表（每类 2 条，按
`sha256(实体 id) % 2` 稳定轮换，不用内置 `hash()`——`PYTHONHASHSEED` 随机化会破坏
「同 seed 同输出」的承诺）。

### 1. `single_chunk` 单块事实（配额 64）

- 判据：`assertions.jsonl` 的 `evidence_text` 在其 `chunk_id` 对应块的正文里
  **恰好出现一次**（`text.count(ev) == 1`），长度 8–40 字。
- 问法：给出原文引文，问它出自哪个文本块。
- 答案：块的 `title`。
- 唯一性是硬要求：同一句话在文中出现两次以上时，"这句话出自哪"就不是一个可判定的
  问题。
- 难度 `easy`；每条 1 条引用、1 个 `gold_chunk_id`、1 个 `gold_assertion_id`。

### 2. `alias` 实体别名与消歧（配额 48）

- 判据：实体的 `aliases` 中 `review ∈ {auto, approved}` 的条目（**权威别名**），
  且存在某个块同时含该别名与实体规范名。
- 问法：正文里「某别名」指代哪个规范名。
- **`pending_aliases` 与 `rejected_aliases` 一律不出题。** 这是 E3 的核心纪律：
  未审的别名连检索表都进不去（`identity.CanonicalEntity.to_dict()` 把三张表分开），
  更不能当标准答案。实测全库 562 条待审别名、0 条拒绝别名，一条都没进入题目。
- 难度 `easy`；无 `gold_assertion_id`（别名是实体身份问题，不对应单条断言）。

### 3. `direct_relation` 两实体直接关系（配额 48）

- 判据：`edges` 中 `support_count >= 2`、`independent_scene_count >= 2`、
  `predicate ∈ vocab.CANONICAL_RELATIONS`（48 个）、两端都不是泛称锚点
  （`identity.is_generic_anchor` 为假）。
- 问法：「A」对「B」处于哪种关系。
- 答案：谓词本身（如 `交谈`）。
- `independent_scene_count >= 2` 是本类最重要的判据：单场景一次共现极可能是抽取噪声，
  跨两个场景独立出现才配当"事实"。
- 难度 `medium`。

### 4. `multihop` 多跳关系（配额 48）

- 判据：`adjacency.json` 中**只走 `out`**（绝不走 `in`），A --边1--> M --边2--> C，
  两条边的 `support_count >= 2`、谓词在词表内、A ≠ C，且**中间实体 M 唯一**
  （存在多个中间实体时问题无唯一答案，直接放弃）。
- 问法：给出两端，问中间实体是谁。
- 为什么只走 `out`：`in` 是同一批边的反向索引，`out` 里的 `undirected` 关系已经
  双向各有一份拷贝，因此正向可达性走 `out` 是完整的。混用 `in` 会让"两跳"变成
  "一条边来回走两遍"，答案退化。
- 难度 `hard`；每条 2 条引用（两条边的证据各一）。

### 5. `cross_chunk` 跨块跨章节综合（配额 32）

- 判据：实体名出现在**至少 2 个不同 `chapter`** 的块正文里，且章节数
  `<= _CROSS_CHUNK_MAX_CHAPTERS`（= 4）。
- 问法：该实体在哪些章节出现过，列出全部章节代号。
- 答案：章节代号集合（`、` 连接）。
- **每章都必须有一条引用块**，且答案列出的章节集合必须恰好等于引用块覆盖的章节集合。
  这条是「不接受答案对但引用错」在本题型上的具体形态：答案写着 `act30side` 而给出的
  引用块全在别的章节，解题者读完块也推不出那一章，题就是不可解的。
- 章节数上限 4 的理由：实测章节数分布
  `{2:720, 3:316, 4:192, 5:98, 6:77, 7:45, 8:48, 9:28, 10:33, 11:32, 12+:137}`。
  上限必须放在**候选池入口**而不是抽样之后——抽完再筛会让配额被白抽掉的候选占走
  （实测那样只有 26/32，缺口 6）；放在池级后 32/32 全额。
- 难度 `medium`。

### 6. `time_conflict` 时间冲突·剧情阶段（配额 32）

- 判据：`assertion.check_qualifier_consistency()` 中 `action == "kept_both"` 的互斥对
  （`vocab.MUTUALLY_EXCLUSIVE_PAIRS`：同盟/敌对、效忠/背叛、保护/交战、治愈/感染、
  驻守/离开、隶属/背叛），且两个断言分处**不同 scene**。
- 问法：同一对实体先后出现两种相反关系，是抽取矛盾还是剧情演进。
- 答案：`时序演进`（附理由）。
- `action == "needs_human"`（同场景冲突）**不出题**——同场景里既同盟又敌对更可能是
  抽取错误，不该拿来考"时序演进"。
- 同一 `(实体对, 谓词对)` 可能有多组互斥断言，按
  `(subject_id, object_id, tuple(sorted((r1, r2))))` 去重，否则同一条问句会重复出现。
- 难度 `hard`；每条 2 条引用、2 个 `gold_assertion_id`。

### 7. `negative_abstain` 否定与不可回答（配额 32）

**7a 否定题**（本类配额的一半，`limit // 2`）——八条判据（`_negation_rows`）：

1. 否定词（`NEGATION_WORDS`：没有/不会/并未/拒绝/不曾/不再）与关系词在**同一句内**；
2. 二者间隔 ≤ 1 字；
3. 关系词后不接名词性后缀（`者病人们性物晶化`）——`感染者`/`矿石病` 里的 `感染`
   不是谓词；
4. 实体名在否定词**之前**、间隔 ≤ 2 字，且间隔字全是连词白名单（`_GLUE_CHARS`），
   或整段是敬称（`_HONORIFICS`：小姐/先生/女士/夫人/大人/殿下/阁下）；
5. 该实体在图上**没有**该谓词的任何边（有边说明否定只是局部表述，不能当整体判断）；
6. 句子含疑问标记（`_INTERROGATIVE`：为什么/难道/是否/吗/？/?/呢）→ 丢弃（反问句
   不在陈述事实）；
7. 名字与否定词之间出现并列否定词（`_PARALLEL_NEG`：也/又/再/还）→ 丢弃；
8. 关系词后接时间后缀（`_TEMPORAL_TAIL`：之后/之前/之时/的时候/时期/期间/过程中）→
   丢弃；另有第二形态：关系词前是「在」且其后 16 字内含时间后缀 → 丢弃
   （`您的命运，并没有在前往北方冰原之后变得一片漆黑` 里「前往」是时间状语）。

答案固定为 `否`，`should_abstain=False`（问题本身可回答，答案是否定）。

**7b 不可回答题**（本类配额的另一半）——真实实体对 + 词表里**不存在**的谓词
（`ABSENT_LABELS`：婚约/祖孙/债主/邻居/寄养/同乡/笔友/代言/代购/陪练），
`should_abstain=True`、`gold_chunk_ids=[]`、`required_citations=[]`。

机检（不是挖掘时的声称）：两实体都在图里；该谓词不在 48 个规范关系内；图上没有任何
边用这个谓词；两实体之间确实没有这个谓词的边（任一方向）。`validate_gold_item` 第 10
条按 id 反查 `_edge_pair_set(edges)`，`audit_goldset.py` 用另一条路径再验一遍。

难度 `medium`。注意本类的 32 条里只有 12 条带引用（否定题），20 条是拒答题。

### 8. `adversarial` 易混淆对抗（配额 16）

- 判据：两实体名一个包含另一个（共享前缀/后缀）、**类型不同**、且存在某块出现了
  **短名**却不出现长名。
- 包含方向的坑：短名是长名的子串，所以「含长名」必然「含短名」，反过来不成立。
  证据块必须按「有短名、无长名」找——按「有长名、无短名」找永远为空（第一版因此
  恒返回 0 条）。
- 问法：「A」与「B」名字相近，是同一个实体吗？若不是，请说明区别。
- 答案：不是同一个；两者的类型分别是什么；**且所引原文只出现短名**
  （这是可逐字复核的事实，不只是模型判断）。
- **题面绝不能写出类型。** 第一版模板是「「{a}」（类型：{ta}）与「{b}」（类型：{tb}）
  是同一个实体吗」——答案就是「类型不同」，题面已经说了，离线自评满分、真实评测
  完全无效。现在模板不带 `{ta}`/`{tb}`，且 `validate_gold_item` 第 12 条会拦。
- 难度 `hard`。

实测方式：把每个 miner 用 `limit=10**6, seed=1` 直接跑真实数据，取返回条数

| single_chunk | 56,778 / 62,910 断言 | 证据唯一且 8–40 字 |

## 五、独立复核抓到的三个真缺陷（为什么需要两条路径）

`scripts/audit_goldset.py` 在产品校验器之外重跑了一遍，抓到：

| 缺陷 | 规模 | 根因 | 修法 |
|---|---|---|---|
| 跨章题答案列章节、引用块没覆盖 | 38 处 | `for chapter in chapters[:3]` 只给前 3 章引用，答案列全部 | 逐章都给引用 + 章节数上限移到池级 + 校验第 11 条 |
| 对抗题把类型印在题面里 | 全部 16 条 | 模板含 `（类型：{ta}）` | 模板去掉占位符 + 校验第 12 条 |
| 校验第 12 条自身误报 | 1 条（`q-ad-000010`） | 实体名「第四集团军军队哗变**事件**」含类型字 | 比较前剥掉两个实体名 |

第三条尤其说明问题：一个为"防泄漏"而写的判据，如果只由写出它的人来验，就会同时
漏掉它自己误杀合法题。外部审计用不同假设重算，才暴露出来。

## 六、已知局限

如实列出，不打算用判据掩盖：

1. **没有双人复核。** F3 需求原文要求「双人复核」。本版本是单人 + 机械复算，属于
   把「标注一致性」替换成「可机检性」。真正的双人复核仍需人工，见第七节。

2. **模板单一，问句可被模板匹配作弊。** 每类 2 条模板，同一类的 48 条题句式几乎
   相同。一个只做表层模式匹配的基线也能拿到不低的分数，这会高估系统能力。缓解：
   八类各自的答案形态不同（标题 / 实体名 / 谓词 / 中间实体 / 章节集合 / 时序演进 /
   否 / 类型对照），单靠模板匹配答不全。彻底解决需要更多模板或人工改写。

3. **否定题靠规则，会漏判也会误判。** 中文否定句的真主语大量是人称代词或跨句
   （「他没去」里的"他"）。实测能确信「否定作用在这个实体 × 这个谓词上」的候选
   只有 **10–21 条**（不同判据版本），当前八条判据给出 12 行 / 10 个独立
   (谓词, 实体) 组合。这是结构性上限：不是判据没收紧，而是这类事实在语料里本来就
   很少以可机检的形态出现。放宽判据能凑到 32 条，但会把「没有一个感染者」当成
   「感染」的否定句——那是错题，不如少给。

4. **单块事实题的难度偏低。** 全部 `easy`，且答案就是块标题，对检索系统几乎无区分
   力。它们的作用是验证「能不能找到那句话所在的块」，不是验证推理。

5. **`time_conflict` 的答案「时序演进」是判断而非事实。** 语料只保证"两种相反关系
   在不同场景都出现过"，"这是剧情演进而非抽取错误"是推理结论。判据要求跨场景
   （`independent_scene_count`）来支撑，但严格说仍需人工确认每一条。

6. **不覆盖多实体、长链推理。** 多跳最多两跳且要求中间实体唯一。三跳以上、需要
   汇总多块信息的题完全没有。

7. **训练/测试分离尚未落地。** F3 原文要求「训练调参集与最终测试集分离」。本版本
   只有一个 320 题的池子，没有划分 train/dev/test。若要用于调参，必须先做划分并把
   测试集封存，否则会污染评测。

8. **seed 只保证同机器同 Python 版本可复现。** 全部抽样用 `_rng(seed)`
   （`random.Random`）+ `_stable_index`（sha256 索引）。`random.Random` 的序列在
   CPython 内部实现变化时理论上可能改变；跨大版本升级后建议重跑并对比。

9. **`alias` 与 `adversarial` 的答案形态依赖图。** 这两类问「规范名」「类型」，答案
   来自 `graph.json`。如果换一版实体归一（`entity_rule_version` 变了），同一批题的
   答案可能变化。跨世代对比时这两类需要重新生成或人工固定答案。

10. **`multihop` 的引用证据句本身常不含端点名字，靠说话人前缀提供指认。**
    96 条 `required_citations` 里只有 6 条（6%）的证据句自身带「说话人：」前缀，
    其余是纯台词。实测（2026-10-31，Lead 独立复核）：48 条多跳题**每一条都至少有
    一条引用所在整行同时含 A/B/C 之一，0 条例外**；但若只看 `evidence` 字段本身，
    48 条里有 **3 条完全不含** A/B/C 任何写法（例 `q-mh-000001` 的证据句
    「你不应当在口袋里放太多东西。」——端点 `云兽` 只出现在该行前缀 `云兽：` 里）。
    影响：引用校验器若只测 `evidence` 子串、不回看所在行，会把这 3 条判成
    「引用不支持结论」。处置：校验一律按整行（含说话人前缀）判，禁止只比 `evidence`。
    生成侧无法消除：抽取出的 `evidence_text` 本就是台词片段，说话人属于轮次元数据。

## 七、后续人工复核操作方式

`gold-v1.json` 的 `items` 是扁平列表，每条自带 `question_id`，可直接导进表格工具。

建议流程：

1. **按 `difficulty == "hard"` 优先。** 96 条 hard（multihop 48 + time_conflict 32 +
   adversarial 16），hard 出错的代价最高。

2. **逐条核对三件事**（不需要看语料以外的任何材料）：
   - 打开 `required_citations` 里的 `chunk_id`，用 `evidence` 在正文里搜索——必须
     **恰好**命中一次；
   - 只看这些块的正文，能否推出 `answer`。推不出 → 该题不合格（这正是跨章题第一版
     的失效形态）；
   - `answer` 是否在 `acceptable_answers` 里（程序已保证，但人工确认措辞合理）。

3. **重点看 `time_conflict` 与 `negative_abstain`。** 这两类的答案含判断成分
   （局限 3、5）。前者要人工确认「时序演进」而非抽取错误；后者要确认否定真的作用在
   那个实体×那个谓词上。

4. **对抗题检查题面是否泄漏。** 第 12 条已机检「类型」二字与类型词，但人工仍应确认
   没有其他形式的提示（例如问句措辞暗示）。

5. **不合格题的处理**：不要直接删（会让占比偏离配额）。把 `should_abstain` 保持
   原值，在外部记录里标 `rejected` 并写明理由，然后重跑
   `py -3 scripts\build_goldset.py --total 320 --seed 20261101` 用同一 seed 重新
   抽样替换——同 seed 同输入必然得到同一批题，人工判定结果因此可叠加。

6. **修改判据后的必做动作**：
   ```powershell
   py -3 -m pytest tests/test_goldset.py -q            # 单测必须全绿
   py -3 scripts\build_goldset.py --total 320 --seed 20261101 --report data\goldset\gold-v1-report.json
   py -3 scripts\audit_goldset.py                      # 独立复核必须 EXIT=0
   ```
   三行都过才算改完。只跑第一行是不够的——单测用的是构造 fixture，真实数据上的
   缺陷（本文件第五节三个）单测抓不到。
