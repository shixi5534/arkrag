  '_pytest_tmp/.../tree/story' != 'E:\\图rag\\_pytest_tmp\\...\\tree\\story'

### 3.3 为什么不现在修

三条理由，不是偷懒：

1. **这些文件是历史结论的证据。** `data/eval_quality_*.json` 是台账里
   198/285、132/195、83/120 那些读数的原始产物。改它们的 `gold_set` 字段，
   等于改证据文件——本项目纪律明写"实验只写新诊断文件，不覆盖历史基线"。
2. **修法需要判断，不是替换字符串。** 把 `E:\图rag\data\goldset\gold-v2.json`
   改成 `data/goldset/gold-v2.json` 会改变"这些产物当初指向哪个文件"的记录，
   需要连同一份说明一起改，否则下一轮又有人问"为什么路径变了"。
3. **它不阻塞任何工作项。** W0–W4 全部不读这些 JSON 的 `gold_set` 字段。

**因此：登记为已知存量债，基线接受 2 failed。** 若要清偿，单独开一项，
写清"改哪个文件、改成什么、为什么这样改不算篡改证据"。

## 4. 本次同时确立的约束（写进基线，不只是记一次）

### 4.1 `pyproject.toml` 刻意不设 `addopts`

曾加过 `addopts = ["-q", "-p", "no:cacheprovider"]`，结果打红了
`tests/test_regression_entry.py`：那条用例起子进程跑一个必然失败的测试，
断言输出含 `"1 failed"`；`-q` 改变了汇总行格式，`"1 failed"` 不再出现。

门报的是"入口没透出失败码"，真实原因是**父进程把汇总格式改了**。
这是本项目记过多次的同型事故：为了让命令短一点而加的参数，把一条判据的
观测面改掉了。**运行时的 `-q` / `--basetemp` 由调用方在命令行显式给。**

### 4.2 起子进程必须传 `env=subproc.child_env()`

`scripts/run_guarded.py` 起初漏了这一条，被
`tests/test_subprocess_encoding.py` 的 AST 扫描抓到。规矩的唯一事实源是
`src/arkrag/subproc.py`：父进程按 UTF-8 解码，子进程就必须按 UTF-8 写管道，
否则中文变 `\ufffd`，或者子进程自己 `UnicodeEncodeError` 退出码 1 ——
与业务失败无法区分。

### 4.3 全量测试约 21 分钟，必须后台跑并轮询

`pytest tests` 实测 1240.89 秒。前台跑会触发工具超时、被移到后台，
而那时**熔断器不生效**（见第 5 节）。正确形态是重定向到文件 + 后台 job + 轮询读文件。

## 5. 与事故记录的关系

本基线**不解除** `docs/事故-内存耗尽与熔断器-20261110.md` 里的运行纪律。
环境标准化降低了"说不清跑的是谁"的风险，但没有降低"一次

- 重型任务串行，不并发。

## 6. 本次顺带修掉的 4 个自造问题 + 2 个既存缺陷

### 6.1 本次引入并已修复

| 失败 | 根因 | 修法 |
|---|---|---|
| `test_subprocess_encoding::test_subprocess_calls_declare_pipe_encoding` | `run_guarded.py` 两处 `subprocess` 未传 `env=` | 按 `subproc.child_env()` 补上 |
| `test_regression_entry` ×2 | `pyproject.toml` 的 `addopts=["-q"]` 改了子进程输出格式 | 删掉 `addopts` |
| `test_suite_hygiene::test_declared_count_matches_actual` | 新增 13 个用例后未更新 `N` | `N: 2017 → 2057` |

### 6.2 查证时发现的既存测试缺陷（在 HEAD `76013be` 上就是红的）

这两条**不是本次引入**，是测试自身写错、长期报假红。修的是观测面，门槛未放宽。

**（1）`test_prod_profile.py::TestDefaultPathIsUnchanged::test_options_none_keeps_the_historical_caliber`**

只在 `fn.args.args`（**位置参数**）里找 `options`，但 `options` 在 `*` 之后，
是**关键字参数**，在 `kwonlyargs` 里；其默认值在 `kw_defaults` 而非 `defaults`。
于是一直报「`ask_once` 没有 `options` 参数」——而参数好好的。
修法：查 `kwonlyargs` + `kw_defaults`。

**（2）`test_prod_profile.py::TestCliWiresTheOptions::test_prod_flag_exists_and_defaults_off`**

```python
class _Cap(argparse.ArgumentParser):   # 继承 argparse.ArgumentParser
...
mod.argparse.ArgumentParser = _Cap     # 然后把它换掉
```

`mod.argparse` 与测试自己 `import argparse` 拿到的是**同一个模块对象**，
所以这是全局替换：`_Cap` 的基类在替换后变成了 `_Cap` 自己 →
构造时 `RecursionError`。而且即便不递归，`mod.main([])` 也会走到
`question == ""` 的早退分支，"`--prod` 默认关"根本没被执行。

修法：改成纯 AST 静态检查（找 `add_argument("--prod", ...)`，
验 `action="store_true"` 或显式 `default=False`），不依赖任何运行期替换。

## 8. 诚实边界

- **本基线只覆盖 `tests/`，不覆盖任何分数读数。** 台账里的
  dev 228/285、holdout 152/195、clean 97/120 是在**旧环境（全局 Python 3.14.3）**
  上测的。换到 3.13 后**尚未重测**，两者不可直接比较。
  要声称分数可比，必须在新环境重跑 `eval_answer_quality` 并出新读数。
- **2 个 failed 是接受的存量债，不是"已经没事"。** 它们会在每次全量跑时红，
  直到有人清债。这本身是好事：存量债应当持续可见。
- **`environment.lock.yml` / `environment.min.yml` 仍未生成。**
  锁文件应由 `conda env export` 产出；本机因未走 `conda env create -f`
  路径（用了 `conda create` 绕开 channels ToS），暂未导出。
- **`conda env create -f environment.yml` 在本机走不通**：被 `defaults` 渠道的
  ToS 拦截。绕法是 `conda create --override-channels -c conda-forge ...`（第 7 节）。
  `environment.yml` 仍是给人读的规格，但复现命令以第 7 节为准。
